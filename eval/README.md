# eval — 发版前手工回归任务集

这是一份「照着跑一遍」的评测清单，不是自动化测试。目的是发版前用固定场景覆盖容易回归的真实能力（文件、浏览器、设备、MCP、自动化、记忆、界面），避免只凭印象手测两三个功能就发版。

## 怎么跑

1. 人工执行：新开一个会话，把 `eval/tasks.json` 里某条的 `prompt` 原文复制发给 agent，按该条 `expect` 逐项核对。建议发版前把全部条目跑一遍，至少跑一遍 `risk=medium` 的条目。
2. 跑校验：`python3 scripts/check_eval_tasks.py`。它只检查清单本身的格式与一致性（字段、id、枚举、重复 prompt），**不执行任务、不联网、不改文件**；发现问题打印清单并以退出码 1 结束，未接入任何构建或 CI。

## 字段

| 字段 | 含义 |
| --- | --- |
| `id` | `分类-三位数`，与 `category` 前缀一致，全文件唯一 |
| `category` | `files` / `browser` / `device` / `mcp` / `automation` / `memory` / `ui` |
| `title` | 一句话，说明这条验证什么 |
| `prompt` | 直接发给 agent 的指令原文，必须自包含、可复制执行 |
| `expect` | 可观察的通过标准：看到什么算过，不写「应该能工作」 |
| `risk` | `low` / `medium` / `high`，表示执行这条对设备或数据的影响面 |

子代理派发归在 `automation` 类（同样是一条自动化执行路径），不单开分类。

## 新增条目

- 复制一条现有结构，字段固定这六个，不增减。
- 先读代码确认真实工具名、参数与返回形态，再写 `prompt`；不要照想象编。
- 用 `~/.aharou/eval-scratch/` 当临时文件目录，不往仓库里写测试垃圾；会改设备状态的任务（闹钟、日历、自动化任务、记忆条目）必须在 `prompt` 里带上清理步骤。
- `expect` 要包含「做错了是什么样」，例如「不能谎称已删」「不虚构工具名」，这样失败时能看出来。
- 加完跑一次 `python3 scripts/check_eval_tasks.py`。
