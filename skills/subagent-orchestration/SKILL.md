# 子代理编排

子代理是由主会话派生的独立工作会话，**上下文与本会话完全隔离**，后台运行、不阻塞主对话。

## 工具：`task`

| action | 用途 |
| --- | --- |
| `create`（默认） | 建子代理并让它开始干活 |
| `send` | 向指定子代理发消息（可反复发），运行中的下一批工具结果里收到，已完成的被重新唤醒 |
| `read` | 读子代理的最后一条输出 |
| `stop` | 停止其执行（取消 AI 任务） |
| `del` | 删除子代理会话及其全部消息 |
| `list` | 列出本会话全部子代理及状态 |

`create` 参数：`prompt`（**必填**，完整指令）、`description`（子会话标题，超 30 字会截断）、`agent`（自定义子代理名，可选）。`read`/`send`/`stop`/`del` 都要 `id`（取自 create 返回的 id）。

## 硬约束

- **最多 5 个同时运行**，超了返回 `MAX_SUBAGENTS_REACHED`——先等一个完成或 `stop` 掉再建。
- **不能嵌套**：子代理的工具集里没有 `task`。
- **不要轮询**：子代理完成会收到系统通知；只有 `task(action="read", id=...)` 看结论时才是主动取。想看完整推导轨迹不靠 read，进它的子会话页看。
- `agent` 写错名字返回 `AGENT_NOT_FOUND` 并列出可用名，**不会静默回退成通用子代理**——写错就改，别硬跑。
- 只能 `read`/`send`/`stop`/`del` 自己派生的子代理，否则 `NOT_YOUR_SUBAGENT`。

## 什么时候派

适合：可独立完成、不依赖本会话细节的任务——大范围调研、批量定位、跨模块审查、跑验证、查资料。通常开 **1~2 个**。

不适合：需要用户实时拍板、或高度依赖对话中已积累的上下文（子代理看不到本会话历史）。

## prompt 必须自带上下文

子代理看不到本会话任何内容，`prompt` 里要写清：

1. **目标与完成标准**：要什么结论、什么算做完。
2. **已知上下文**：文件路径、已核实的结论、已排除的方向、用户约束。
3. **边界**：不该动什么（哪些文件、哪个分支、是否只读）。
4. **期望产出**：结论形式、是否要 `文件路径:行号` 引用。

派生后可以继续 `send` 补指令或纠偏，纠错比重新派一个划算。

## 自定义子代理

两级目录，同名时**项目级优先**：

- 全局：`~/.aharou/agents/<name>.md`
- 项目级：`<工作区>/.aharou/agents/<name>.md`（远程模式下指服务器上的工作区）

App 内「设置 → 子代理」新建与手写 `.md` **完全等价**。frontmatter 字段：

| 字段 | 说明 |
| --- | --- |
| `name` | 标识，省略时取文件名 |
| `description` | 何时该用它的简述，主会话靠它判断是否选用 |
| `provider` / `model` | 省略则继承父会话 |
| `reasoningEffort` | `none`/`low`/`medium`/`high`/`xhigh`/`max` |
| `mode` | `build`/`plan`/`auto`，省略继承父会话当前模式 |
| `tools` | 工具白名单，**省略＝开放全部可用工具** |
| `disallowedTools` | 工具黑名单，优先级高于白名单，支持 `mcp__*` 通配 |
| `inject` | 注入的规则片段（见下） |

`inject` 取值：`base`（轻量基线：工具规范+路径约定）、`mainRules`（完整通用规则）、`skills`（技能清单）、`memory`（记忆摘要）、`projectRules`（工作区 `AGENTS.md`/`CLAUDE.md`）。`base` 与 `mainRules` **只选一个**，同时开会注入两遍重叠文本。省略 `inject` ＝ `[base, skills, memory, projectRules]`；写 `inject: [none]` 则只用正文提示词。

**内置 Explore**：只读探索子代理，落在 `~/.aharou/agents/explore.md`，只在文件不存在时释放一次，用户改动升级不丢。工具集只有检索类（`readFile`、`list`、`search`、`websearch`、`webfetch`、`loadSkill`），**无写文件与执行命令能力**——代码库梳理、查调用链优先派它。

## 生效与授权

- 新增、改名、改定义后，**已打开的会话仍用开场时的清单，得新开会话才看得到改动**（`task` 报找不到定义时提醒用户这一点）。
- 子代理与主会话同一套授权机制：它尝试写文件/跑命令同样会弹窗，弹窗标明来自哪个子代理。
- **子代理继承派发时的模式**：PLAN 下派出的同样只读；AUTO 下与主会话一样自动放行（`Shizuku` 除外）。
- 「设置 → 子代理」里禁用后，它不再出现在可派发清单里，也指不到名；已在运行的子会话不受影响。

## 交付与收尾

- 子代理完成时主会话自动收到通知，读其**最终产出**汇总给用户，不要把中间日志全倒出来。
- 用户手动停止/删除运行中的子代理时，主会话收到的是「已被手动终止」，**不要自己重新派一个**；并发名额会立即释放。
- 派之前先跟用户说清楚要派几个、干什么；一次别开太多，名额和上下文都有限。
