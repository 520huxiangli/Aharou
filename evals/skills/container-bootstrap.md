# 验收用例：容器环境初始化（`container-bootstrap`）

## 应该触发

- 「容器里没有 python」
- 「装个 node」
- 「换下软件源」
- 「帮我装 Android SDK」

## 不该触发

- 「帮我写个 python 脚本」—— 环境已经能用，这是写代码不是装环境
- 「这个包怎么用」—— 用法问题，不是安装问题

## 验收点

- [ ] 装系统包 / 全局工具前先说明「缺什么、装什么、装在哪」，等确认后再动手
- [ ] 没有自行降级、换源、删锁文件强行装
- [ ] 装包报错时先想到硬链接那个坑（proot 参数加 `--link2symlink`），而不是反复重试或怪网络
- [ ] Android / Flutter 这类重场景建议装进 Debian / Ubuntu 镜像（内置 Alpine 用 musl，踩坑）
- [ ] 耗时安装用后台方式跑并先告知预计耗时，没有空等
- [ ] 新装的环境变量在**新开的终端**里才生效，没有因为老终端里看不到就判「装失败」

## 怎么手工验

在一个干净容器里说「装个 python」，看它是否先报清单等确认；装完在**旧终端**里问它为什么没有 `python3`，看它是否解释「要新开终端」而不是重新装一遍。
