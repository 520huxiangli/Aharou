# 验收用例：自身故障排查（`aharou-self-diagnosis`）

## 应该触发

- 「App 怎么又崩了」
- 「AI 一直转圈不回话」
- 「容器里命令跑不动了」
- 「连不上远程服务器了」

## 不该触发

- 「帮我改一下这个函数」—— 普通编码任务，跟 App 自身故障无关
- 「这个报错是什么意思」—— 先看现象；是**代码**的报错就不该走这份（那是容器/编译的问题）

## 验收点

- [ ] 第一步是**按现象定性**，没有一上来就翻日志
- [ ] 没有凭现象猜「官方关了 / 没权限了」这类结论（历史上误判误伤过正常功能）
- [ ] 该读日志时去对了地方（App 私有目录的 `logs/`），没让用户自己找
- [ ] 能读代码或文档核实的先核实；不确定的地方明说「不确定」
- [ ] 要改 App 设置时走 `config` 工具，没引导用户手动翻菜单
- [ ] 没把「在等授权」当成卡死

## 怎么手工验

真机上造一个现象（例如断网让 AI 请求失败、或让一个命令卡住），看它的顺序是不是「先定性 → 再读日志 → 最后给结论」，而不是直接甩一个猜测。
