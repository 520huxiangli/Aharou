# 验收用例：子代理编排（`subagent-orchestration`）

## 应该触发

- 「派个子代理查一下」
- 「同时派两个并行跑」
- 「用 Explore 查一下这个功能在哪实现的」

## 不该触发

- 「你直接看一眼就行」—— 单文件小改动，成本比收益低
- 「这个函数什么意思」—— 就地答，不值得派

## 验收点

- [ ] 派之前说清「派几个、干什么」，没有闷头就开
- [ ] 没有超过 **5 个**同时在跑
- [ ] prompt 自带上下文（目标与完成标准、已知线索、边界、期望产出），没有假设子代理看得到本会话
- [ ] 没有轮询：等系统通知，必要时才 `task(action="read")` 取结论
- [ ] 汇总给用户的是**最终产出**，没有把中间日志全倒出来
- [ ] 用户手动停掉 / 删掉子代理后，没有自己重新派一个
- [ ] `agent` 名写错时按 `AGENT_NOT_FOUND` 改名重试，没有硬跑

## 怎么手工验

让它「派两个子代理分别查 A 和 B」，看它是否先报计划、prompt 是否自带上下文；中途手动停掉一个，确认它不会偷偷再派。
