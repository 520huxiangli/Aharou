# 机器人接入

把 Aharou 接进聊天软件里：你在微信 / 飞书 / QQ / Telegram 里发消息，它在本机跑 agent 并回你。

四个平台都走**长连接**（长轮询或 WebSocket），**不需要公网地址、不需要服务器**——手机自己连出去即可。

## 各平台对照

| 平台 | 需要准备 | 连接方式 | 消息限制 |
| --- | --- | --- | --- |
| **Telegram** | BotFather 拿到的 token | 长轮询 | 单条 4096 字，超长自动分条 |
| **微信** | iLink 绑定后的 botToken + ilinkUserId | 长轮询 | 用户发消息后 **24 小时内**才能回 |
| **飞书** | 自建应用的 App ID + App Secret | WebSocket 长连接 | 不用配回调地址 |
| **QQ 官方机器人** | 开放平台机器人的 AppID + App Secret | WebSocket 网关 | 长期未使用会被平台回收 |
| **个人 QQ** | 按需安装 NapCat，扫码或账号密码登录 | 本机 OneBot 连接 | 依赖 Linux QQ 兼容版本和手机后台运行条件 |

> 凭证全部由你自己填，**App 不内置任何人的身份**，也不会随备份外传。

## 通用流程

1. 打开「设置 → 机器人接入」，选一个平台
2. 填该平台的凭证，打开开关
3. 在聊天软件里给机器人发一句话
4. 它会回你一个 **6 位配对码**
5. 回 App 的同一页面，在「待配对」里点**通过**
6. 之后再发消息就会直接由本机 agent 回答

配对是**按渠道**记录的：四个平台的已配对列表各自独立，同一个人换平台要各配一次；某个平台里通过的人也不会在另一个平台被放行。旧版本升级上来的配对记录会自动归到对应平台的列表里，不需要重新配对。不想要了就点「移除」。

也可以先打开开关再填写参数：配置不完整时等待补齐，填完整后会自动连接，不必先关再开。修改连接配置会结束旧连接并按新配置重连；相同配置重复保存不会反复重连。

工具需要审批时，按钮或文字审批独立于正在执行的长回合处理，不会排在该回合之后。只有实际解决了仍待决的审批才会回复已允许或已拒绝；点击过期或已经处理过的审批会提示失效，不代表任务已经执行成功。

Telegram 的已接收待处理消息会先暂存在应用私有目录，再继续拉取下一页，避免消息积压时取不到后续审批。处理确认按连续顺序推进；应用异常退出后可以重放尚未确认的消息，但工具执行与消息确认不是同一个事务，极端情况下仍可能重复执行。回复发送失败不会仅为补发正文而重新执行整个任务；遇到这类失败可以查看日志并从应用内会话取回结果。

## 微信（iLink / ClawBot）

两种绑定方式，任选其一：

**扫码绑定（推荐）**
1. 在「设置 → 微信机器人」点「扫码」
2. 用微信扫弹出的二维码，手机里确认
3. 状态从「待扫描」→「已确认」后凭证自动填入，不用手抄

**手动填凭证**
1. 在微信侧完成 ClawBot 绑定，拿到 `botToken` 与 `ilinkUserId`
2. 两样都填进设置页，接入地址留空（默认官方 iLink）
3. 打开开关

**注意 24 小时限制**：用户发来消息后 24 小时内你才能回。超时后要等对方再发一条——这是微信侧的策略，App 无法绕过。

**这个平台没有按钮**：工具需要授权时，机器人会发一条带说明的文本，回「允许」或「拒绝」即可。

## 飞书

1. 在飞书开放平台建一个自建应用，开启机器人能力
2. 复制「凭证与基础信息」里的 App ID / App Secret 填进设置页
3. 打开开关（事件走 WebSocket，不用配回调地址，也不用内网穿透）

**平台侧还有三件事必须做，少一件服务端都不会推消息**（代码这边改不了）：

- 「事件与回调」里的订阅方式选 **使用长连接接收事件**（不是「请求网址」）。保存时客户端要在线：先把 App 里的开关打开、看到状态变成已连接，再回后台保存
- 在事件订阅里添加 **接收消息 `im.message.receive_v1`**
- 应用**已创建版本并发布**（草稿版本的订阅不生效）

另外两点容易踩：**同一个 App ID 不要同时开在别的设备或程序上**——飞书长连接是集群模式，多个客户端在线时事件只会投给其中一个；**单聊直接发就行，群里必须先把机器人拉进群、发消息时 @ 它**，飞书只推 @ 了机器人的群消息。

仍然收不到时看 App 日志（设置 → 日志），按顺序找这几行：`准备建立长连接` → `长连接已建立` → `收到服务端 ping` → `收到事件帧`。有前两行没有事件帧，就是平台侧配置问题；有事件帧但后面跟着「丢弃事件」，日志会直接写出原因。

## QQ

QQ 设置页分为「官方机器人」和「个人 QQ」。切换页面分区只改变当前显示，不停止另一种服务；原有官方机器人的凭证与会话保持不变。

### 官方机器人

1. 在 QQ 开放平台（`q.qq.com`）创建机器人
2. 创建成功页会给出 **AppID** 与 **AppSecret**——**AppSecret 只显示一次**，务必当场存好
3. 两样填进设置页，打开开关

单聊直接把消息发给机器人；群里要先把机器人拉进群，发消息时 @ 它。连接靠定时心跳保活，掉线会自动重连，断开时日志里会写明关闭码和原因。平台侧对长期未使用的机器人有回收策略，被回收后需要重新创建。

### 个人 QQ：NapCat

个人 QQ 不需要开放平台 AppID 或 AppSecret。Aharou 自动安装并管理独立的 Debian 环境，用于运行 Linux QQ 和 NapCat，不要求另外安装 Termux 或准备服务器。无论当前开发容器使用哪个镜像，都不需要为了 QQ 机器人切换容器；NapCat 不会替换或修改当前开发容器。机器人运行环境和 AI 执行任务所用的工作区是两回事，工作区仍按自己的设置使用对应容器。

1. 打开「设置 → QQ 机器人 → 个人 QQ」，点「安装 NapCat」。已同步的固定版本资源优先从 Aharou 的 CNB 分发仓下载，失败后尝试对应的官方来源；两个来源使用同一份固定摘要校验。尚未同步的新版本仍使用官方来源，不会套用旧版镜像地址。首次使用还需联网安装 Debian 依赖，这部分使用华为云 Debian 国内镜像，主仓库、更新仓库和安全仓库一致配置；CNB 负责固定安装包，国内 apt 源负责依赖。依赖源仅用于 NapCat 的安装和更新，不修改日常开发容器的软件源；镜像索引或签名校验失败会显示错误，不混用旧官方源缓存继续安装。页面和常驻通知显示当前阶段，下载时显示进度，解压或安装依赖时显示活动指示和最新输出，不把固定阶段进度当作下载百分比。离开设置页不会取消安装，可从页面或通知取消；重复点击不会重复启动。安装、更新使用独立前台服务，完成、失败或取消后释放，不会自动重新安装。系统强行结束整个应用仍可能中断任务，前台服务不保证永久存活。
2. 安装完成后点「启动」，等待运行状态就绪。
3. 点「打开扫码登录」，在应用内的 NapCat 登录页扫描二维码并确认。二维码失效时可刷新；也可以提交 QQ 账号密码，出现验证码或新设备验证时进入登录验证页面继续。
4. 登录后查看账号信息和「消息连接」状态。进程运行、QQ 已登录与 AI 消息已连接是不同状态，不能只看启动按钮。
5. 设置允许的私聊账号、群号和群聊是否仅被 @ 时响应，保存后生效。群聊默认关闭，自消息响应默认关闭；开启自消息响应后仍会忽略机器人刚发出的消息，避免循环回复。

账号密码输入框只在当前界面内存中暂存，提交后清空。QQ 的专用数据目录和上次登录账号会保留；普通停止、服务异常和覆盖更新不会作为退出账号处理。重新启动时会尝试恢复上次登录；旧版本未记录账号时，只在官方历史登录列表中存在唯一账号时尝试恢复，多个账号不会自动猜选。恢复失败或票据过期时，再进入登录页完成验证。

页面分别显示正在确认、未登录、管理服务不可用和服务已停止，不会因为暂时无法读取状态就认定账号已丢失。恢复期间保留上次账号显示，但只有服务确认在线后才接收 AI 消息。已开启的服务会在应用回到前台时补恢复；系统不允许后台启动或启动失败时，可点「恢复运行」重试，不需要反复关闭开关或重新安装。QQ 可能要求额外验证，也可能限制第三方接入，不能保证每个账号都能成功登录或持续在线。

**消息范围与账号隔离**：允许的私聊账号只限制私聊，允许的群号只限制群聊。明确设置的允许列表用于授权对应聊天；留空不表示把本机 AI 开放给所有人，仍会保留首次聊天绑定的限制。不同登录账号、官方机器人与个人 QQ 的会话及绑定相互隔离。每条消息会把所属渠道、聊天标识、发送者标识和可用昵称一起交给 AI，并随该条历史保留，因此同群不同发言者可区分。昵称和群名只是显示信息，不是身份认证或操作授权；个人 QQ 的号码与官方机器人的 openid 不会自动视为同一身份。

**工作区与模型**：在「新会话默认值」选择工作区和模型，只影响之后创建的 QQ 会话，已有会话保留自己的设置。未指定工作区时使用创建会话当时的当前工作区；当前也没有工作区时，会自动创建或复用 `im-robots` 机器人工作区，不主动切换你正在看的项目。其他机器人在没有当前工作区时也使用这个兜底。

**高级管理与日志**：常用操作在 Aharou 设置页完成，NapCat 专属的详细配置从「打开高级 WebUI」进入。安装阶段和命令输出会实时进入脱敏日志，安装期间也能查看、复制或分享，分享前仍建议检查内容。日志同时写入应用日志，离开设置页后仍可查对应安装记录；页面日志只保留本次应用进程中的最近记录，不会在重启后假装仍在安装。高级设置修改端口或连接凭据后，需要保持 Aharou 的连接配置一致。

**停止、退出与更新**：关闭页面不停止机器人；点「停止」结束本机受管进程和消息连接，保留登录数据。「退出本机账号」会停止运行并切换到新的未登录档案，保留原账号的本机资料，不等于在腾讯服务端吊销设备授权。需要撤销时，请在 QQ 的登录设备管理中移除对应设备；本机退出失败会显示原因。更新仅替换程序版本，保留登录资料和配置，失败时不清空用户数据。

运行环境与登录资料保存在应用专用目录，不属于某个工作区。首次下载、安装依赖和启动 QQ 会占用存储、内存及电量；息屏保活仍受手机系统限制。安装失败时先查看页面错误和日志，下载错误会指出失败的文件和来源；无需切换当前开发镜像，也不要通过清空应用数据来重试。

## 图片和文件

- **收**：四个平台都支持。对方发来的图片、文件、语音会自动下载，交给本机 agent 读（存在应用私有目录 `files/aharou/im_files/`）
- **发**：飞书、QQ、Telegram 支持；**微信暂不支持**（iLink 的上传参数格式没有公开文档，不猜着实现）

语音会按各平台原始格式保存，能不能直接播放取决于格式（微信是 silk，需要解码）。

附件下载失败时会列出未能接收的文件，提醒重新发送。部分附件成功时，AI 仍可处理已收到的材料和正文，但会同时知道输入不完整；全部附件失败且没有文字说明时，只提示重发，不会启动没有材料的分析。

需要 AI 排查连接时，可以让它查询各渠道的实际连接状态和脱敏错误。启用开关只表示配置，实际状态会区分已停止、连接中、已连接和错误；查询不修改设置，也不返回机器人凭证。

## 常见问题

**开关打开了但状态一直「未连接」**
先看凭证是否填全（每个平台都要求两项）。飞书/QQ 还要确认应用里已经开启了机器人能力。

**收不到消息**
检查配对是否通过——未配对时的消息只会回配对码，不会进 agent。现在是按渠道分开的，确认你看的是对应平台那一页的列表。

**飞书连上了但发消息没反应**
多半是飞书后台的订阅方式/事件订阅/应用发布没配好，见上面「飞书」一节的三条。日志里能看到连接是否建立、有没有收到事件帧。

**QQ 用一阵子就不回消息了**
旧版本没有心跳，会被网关静默断开；现在会定时心跳并自动重连。如果仍然出现，看日志里有没有「网关连接已关闭」以及关闭码。

**回复很慢**
长回复会分段发。Telegram 支持原地刷新（能看到内容逐渐长出来），微信不支持编辑消息，只能在跑完后一次发出。

**会不会很耗电**
只有打开开关时才有长连接。不用了把开关关掉即可，前台通知里也有「停止」按钮。
