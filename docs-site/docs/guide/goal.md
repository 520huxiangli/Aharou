# 会话目标（goal）

给一个会话定一个长期目标，AI 就不再「回一轮就停」——每轮结束后它会自己接着往下推，直到目标达成、你叫停，或者预算用完。

适合这类需要连续多轮才能完成的事：把某个模块的重构做完、把项目里的 lint 警告清干净、按一份需求清单逐条实现。

## 设定一个目标

在输入框里输入：

```
/goal 把 app 模块里所有 TODO 注释清掉，每处都补上说明或实现
```

回车后目标立刻生效并开始第一轮。输入框上方会出现一条目标条，显示目标正文、当前状态和已经跑了几轮。

目标属于**当前会话**：切到别的会话就是另一份目标，两者互不影响。

想换目标，直接再发一条 `/goal 新的描述` 就行。旧目标连同它的轮数与用量一起作废，从第一轮重新开始。

输入 `/` 时会看到 `goal` 也在命令列表里，描述与这里一致。

## 查看、暂停与清除

| 输入 | 作用 |
| --- | --- |
| `/goal` | 查看当前目标：状态、已跑轮数、正文 |
| `/goal pause` | 暂停：之后不再自动续跑 |
| `/goal resume` | 恢复：重新开始自动推进，并立刻跑一轮 |
| `/goal clear` | 清除目标（`/goal off` 等价） |

目标条右侧的两个按钮就是「暂停 / 继续」和「清除」，不必再敲命令。

`/goal` 的查看结果、暂停与清除的提示都会作为一条助手消息出现在聊天里。这类提示只是给你看的，不会进入上下文，也不会影响之后的回答。

## 自动循环是怎么跑的

- 每轮正常结束后，只要目标还在进行中，Aharou 会自动再发一条继续指令，让 AI 接着推进；
- **你说的话优先**：AI 正在跑时你发的消息会先排队，等这一轮结束先处理你的消息，目标续跑让位；
- 点输入框上的停止键会中断当前这一轮，同时把目标置为暂停——不会出现「停了一下又自己跑起来」；
- 续跑的每一轮不会在你的消息列表里留下伪造的用户消息，历史里只有 AI 的实际回复。

## 什么时候会停

目标条上的状态会随情况变化：

| 状态 | 含义 |
| --- | --- |
| 进行中 | 每轮结束自动续跑 |
| 已完成 | AI 确认目标里的每一条要求都已达成且有证据 |
| 已暂停 | 你点了暂停，或者按了停止键 |
| 受阻 | 连续多轮没有任何实际进展，AI 判定推不动 |
| 预算耗尽 | 轮数或 token 用完 |

「已完成」由 AI 自己判定：它会对照目标里的每一条要求，逐条确认都做到、并且有证据（命令输出、文件改动之类），才会标为完成。只要还缺一条，它就不会标。

停下来的状态都不会丢目标。处理完问题后发 `/goal resume` 就能接着推进。

## 两种预算

在 **设置 → 通用设置 → 偏好设置 → 目标（goal）** 里有两行可以改：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 最多续跑轮数 | 50 | 一个目标最多自动推进多少轮 |
| token 预算 | 500000 | 目标循环累计消耗的输入与输出 token 上限 |

两个预算哪个先到就在哪停，状态显示为「预算耗尽」。

预算从**设定目标的那一刻**开始累计：暂停和恢复都不会重置轮数与用量，只有重新 `/goal` 设一个新目标才会从零重来。

预算用完不等于目标作废：把数值调大，再 `/goal resume` 就能继续。

## 与运行模式的关系

- 设定目标时会话如果正处在 PLAN 模式，会先切回 BUILD 模式——自主循环需要能改文件、跑命令，只读模式里无从推进；
- 循环里的每一轮仍然走正常的权限控制：BUILD 模式照旧逐次确认，AUTO 模式照常放行。目标不会替 AI 跳过任何授权。

## 常见问题

**目标条变成「受阻」了怎么办？**
说明 AI 连续好几轮都没做成任何实际动作（没改文件、没跑命令、没实质产出）。翻一下它最后停在哪个问题上，把缺的信息或权限补上，再 `/goal resume`。

**预算很快就耗尽了？**
多半是目标写得太宽。一个目标里塞五件事，前几轮就容易烧完预算；拆成几个小目标、分几次 `/goal` 更划算。

**暂停之后它还会自己跑吗？**
不会。暂停只保留目标内容，自动续跑已经停掉；你手动发消息仍然会正常得到回复。

**换个模型会不会清掉目标？**
不会。目标跟着会话走，和当前用哪个供应商、哪个模型无关。

**清除目标后还能找回吗？**
不能。清除会连目标正文、轮数和用量基线一起清掉，需要的话重新 `/goal` 设一次。
