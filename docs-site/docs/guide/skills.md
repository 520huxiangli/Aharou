# 技能

技能是为 AI 提供的「专项能力扩展包」——把某类任务的标准流程、最佳实践与专属知识沉淀为规范指南，AI 遇到相关任务时会自动按需加载执行，无需你在每次对话中反复交代背景规则。

入口在「设置 → 技能」。已启用的技能会出现在对话输入框的 `/` 菜单里，可以直接用 `/技能名` 触发，也可以带参数（如 `/pdf-report a4`），详见[对话与消息](./chat.md)的〈斜杠命令〉。

## 技能从哪里来

一个技能就是一个目录，里面有 `SKILL.md`（或兼容的 `CLAUDE.md`）就会被自动识别。分三级：

- **内置技能**：随 App 打包，开箱就有（如配置通道说明、第三方 App 操作规范）。**不能删除也不能编辑**，列表里带「内置」徒标，也不参与启停。
- **全局技能**：放在 `~/.aharou/skills/`，跨项目共享，App 升级不丢。
- **项目级技能**：放在 `<工作区>/.aharou/skills/`，只在当前工作区生效，可以随项目提交到 git。远程模式下这里指的是**服务器上**的工作区，读写经由 SSH 完成。

同名技能优先级：项目级 > 全局 > 内置。

你可以直接在 App 里新建技能（见下文），也可以从技能市场安装（见下文），或者在容器里手工创建技能目录。App 会监听技能目录，手工添加、删除、改名之后列表几秒内自动刷新，不用重进页面。

## 列表页

按「当前项目 / 全局」两个可折叠分组显示，点分组标题展开或收起。

每行是一个技能：图标、名称、描述摘要，名称右侧的彩色勋章表示启用或禁用状态。点行进详情；左滑露出删除按钮，删除会弹确认框——它会直接移除技能目录，**不可恢复**。

右上角「＋」添加技能（见下文〈添加技能〉）。

## 添加技能

点右上角「＋」弹出底部选择单，先选**作用域**（全局 / 当前项目，默认全局），再选添加方式：

- **手动新建**：进入编辑页，填写名称、描述与正文，从头建一个技能。
- **从文件导入**：选择一个 `.md` 文件（`.markdown` / `.txt` 也可）。App 读取文件内容，按其 frontmatter 的 `name`/`description` 建技能，缺 `name` 时用文件名兜底，写入 `<作用域>/skills/<名称>/SKILL.md`。
- **从压缩包导入**：选择一个 `.zip`。App 解压后识别包内所有含 `SKILL.md`（或 `CLAUDE.md`）的目录，逐个导入——一个包可以带多个技能，常见于 GitHub 仓库的打包下载。
- **从市场安装**：进入技能市场挑选并安装（见下文〈技能市场〉）。

导入与手动新建等价：文件一律归一化为 `SKILL.md` 落盘，之后照样能用编辑器或容器命令改。

**几种会被跳过的情况**（会弹窗逐个列出原因，不影响其余技能）：

- 技能名称不合法（含 `/` `:` 等不能做目录名的字符、为空或过长）；
- 目标作用域下已有同名技能（不会覆盖）；
- 技能正文为空；
- 压缩包里没有任何含 `SKILL.md` 的目录（整体失败）。

## 详情页

三张卡片：「是否启用」（名称、来源和启停开关）、「摘要」（描述）、「正文」（`SKILL.md` 的完整内容，等宽字体，可以选中复制）。

内置技能没有启停开关，也没有编辑按钮。

右上角的铅笔按钮进入编辑页。

## 新建与编辑

编辑页有两组内容：

- **基本信息**：名称、描述、作用域。名称就是 AI 加载技能时用的标识，建议用英文小写加连字符（如 `pdf-report`）；描述写「何时该用它」，AI 靠这句话判断要不要加载；作用域选「当前项目」或「全局」，决定技能目录落在哪一级。
- **指令正文**：技能的完整指令，支持 Markdown。写清这类任务的标准流程、约束与注意事项。

名称和正文都填了才能点右上角「保存」。保存后会写成 `<技能目录>/SKILL.md`，与手写的技能完全等价，之后照样可以用文本编辑器或容器命令改。

几个需要留意的地方：

- **作用域只能在新建时选**。已有技能的作用域是灰的——换作用域等于搬目录，需要你自己在容器里移动。
- **改名只改 `SKILL.md` 里的 `name`，不动目录名**。技能正文里常按 `~/.aharou/skills/<目录>/run.py` 引用同目录脚本，目录跟着改名会把这些引用打断。
- 编辑的是从 GitHub 装来的技能时，如果它用的是 `CLAUDE.md` 而不是 `SKILL.md`，保存会写回原来那个文件，不会多出一份。
- 同一作用域下已有同名技能、名称含 `/` `:` 等不能做目录名的字符、或正文为空时，保存会失败并在页面顶部给出红色提示。

## 技能市场

入口：设置 → 技能 → 右上角「＋」→ **从市场安装**。装上的技能就是一个普通技能，可以编辑、禁用、删除。

预置了四个源：Aharou 官方、Anthropic 官方、Trae 社区、腾讯 WorkBuddy。点源名切换，列表里显示该源技能的名称、描述与作者、版本、许可，右侧是「安装」（已装过显示「已安装」，有新版显示「更新」）。源多了一个屏幕放不下时可以左右滑。

其中「Aharou 官方」里的技能是我们自己写的，随 App 仓库更新：

| 技能 | 用来干嘛 |
| --- | --- |
| 自身故障排查 | App 崩溃/卡顿、AI 请求反复失败、连不上服务器时，先看日志定性的流程 |
| 宿主设备管理 | 用 shell 身份装/卸应用、抓 logcat、截屏、跑 dumpsys |
| 面板脚本编写 | 写「自定义面板」的卡片脚本（余额/配额/Token 看板） |
| 容器环境初始化 | 首次进容器、换软件源、装 Node/Python/JDK，以及已知坑 |
| 子代理编排 | 何时派子代理、prompt 要怎么写、自定义子代理定义 |

这些是「按需装」的：不装就不会占用任何上下文，装完 AI 在对应场景才会加载它。

**粘贴仓库地址**：顶部输入框可以直接贴仓库地址，从里面挑技能装，支持：

- GitHub：`github.com/某人/某仓库`
- Gitee：`gitee.com/某人/某仓库`
- GitLab：`gitlab.com/某人/某仓库`
- Gitea / Forgejo 等自建实例（按域名识别）
- 简写 `某人/某仓库`（按 GitHub 处理）

带上分支和子目录也行：`github.com/某人/某仓库/tree/main/skills/docx` 会只扫 `skills/docx` 那一层。**仓库里凡是含 `SKILL.md` 的目录都会被列出来**，所以整个仓库有多个技能时会一次列出；整个仓库就一个技能（`SKILL.md` 直接放在仓库根目录）时也认得出来。

技能网站的地址也认：

- `skills.sh/某人/某仓库`（带技能名也行，如 `skills.sh/anthropics/skills/pdf`）—— 直接换算成它背后的 GitHub 仓库
- `lobehub.com/skills/某技能` —— 先读一次那个技能页，找出它的仓库再列

技能网站给的技能名不一定等于仓库里的目录名（skills.sh 的 `/anthropics/skills/pdf` 在仓库里其实是 `skills/pdf`），所以按子目录没扫到时会自动退回整个仓库，从列表里挑就行。

**站点的目录页地址**（如单独的 `skills.sh`、`lobehub.com/skills`）拿不到技能清单——它们没有「列出全部技能」的公开接口：

- 贴 `skills.sh` 会提示你用下面的关键词框搜（它就是那个站，没有「列全部」的入口）
- 其它技能站的目录页会提示你贴到具体技能那一级

## 关键词搜索

页面上有两个常驻的输入框：**上面的填网页地址（点「加载」），下面的填关键词（点「搜索」）**。搜索走的是 skills.sh 的公开检索——它只开了关键词接口、没有「列全部」的入口，所以要靠你输词去拿。**关键词至少 2 个字**，不够按钮是灰的。

搜索结果一次最多 100 条，每条显示技能名和来自哪个仓库。列表里的技能来自全球各个 GitHub 仓库（Anthropic、Vercel、微软、Prisma 等），**点「安装」时会自动到它所属仓库里找到对应目录再下**，不用你手动找路径。

搜索是在线的，结果不缓存，换个词就是一批新结果；搜索跟上面选中的是哪个源无关，结果会直接替掉列表。

技能多的源（比如 WorkBuddy 有近三百个）会**先把技能名铺出来、描述随后补上**，不用等全部读完才看到列表。

列表优先显示仓库自带的中文名与中文描述（`display_name` / `description_zh`，WorkBuddy 这类国内仓库都带了）；仓库没提供中文时按界面语言回退。显示名与技能标识不同时，标识会另起一行小字放在下面——调用技能、排查问题时认的是它。

访问 GitHub 走的是加速通道，不用自己挂代理；如果连不上会明确提示「加载失败」，跟「这个源里没有技能」是两种提示，不会混淆。

装到全局还是当前项目，由页面顶部的「作用域」决定。**同名技能会被覆盖更新**——在技能市场里点「安装」就是对「更新」的语义。

列表结果会缓存 12 小时，再次进入同一个源秒开（目录型源要逐个读每个技能的 `SKILL.md`，不缓存每次进来都要重跑）。

> 市场里的技能来自第三方仓库，安装前留意作者与许可信息。Anthropic 官方源里的 `docx` / `pdf` / `pptx` / `xlsx` 是 source-available 许可，不是开源，用前先读它的许可条款。

**自己加源**：除了预置源，还可以通过配置通道加自定义源（路径 `skill_market.sources`）。新增一项需要 `id` / `repo` / `path`，可选 `branch`（默认 `main`）、`kind`（`directory` 扫目录 / `index` 读 JSON 索引，默认 `directory`）、`host`（`github` / `gitee` / `gitlab` 或 Gitea 系域名，默认 `github`）。

## 启用与禁用

详情页的开关控制这个技能是否参与 AI 会话。禁用后它不再出现在系统提示的可用技能清单里，AI 也无法加载，可以减少上下文占用——技能装多了之后这个开关很有用。

禁用名单写在 `skills.json` 里（全局是 `~/.aharou/skills.json`，项目级是 `<工作区>/.aharou/skills.json`；远程模式下项目级名单存在手机本地，按工作区隔离），格式是：

```json
{ "disabled": ["技能名"] }
```

两级取并集，任一作用域禁用即生效。也可以直接手工编辑这个文件，几秒内自动生效。

## 投稿到官方源

你自己写的技能也可以进官方源，让所有人在「技能市场 → Aharou 官方」里装到。两条路，任选一条：

- **直接提 PR**（更快）：fork [Aharou](https://github.com/520huxiangli/Aharou)，在 `skills/<标识>/SKILL.md` 加上你的技能，提交 PR。
- **提 Issue**：用[技能投稿](https://github.com/520huxiangli/Aharou/issues/new?template=skill_submission.yml)模板，把技能标识、中文名、描述和 `SKILL.md` 正文填进去，等审核。

收录规范：

- **frontmatter 三个字段**：`name`（英文小写加连字符，等于目录名）、`display_name`（市场里显示的中文名）、`description`（何时该用它——AI 靠这句判断要不要加载）。
- **要有输入输出、能拿到结果**：写清标准流程、约束与注意事项，而不是只讲思路。
- **依赖写清楚**：用到什么工具包，在正文开头说明怎么装。
- **别放敏感信息**：正文里不要写 API Key、令牌、私人地址。
- **许可**：提交即同意以 GPL-3.0 收录；改编自别处的技能请注明来源与许可，我们会登记到 `NOTICE`。

合并进 `master` 后不用等发版——官方源读的就是仓库 `master` 分支的 `skills/` 目录，刷新一下市场就能看到。
