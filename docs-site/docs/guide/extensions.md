# 扩展

「扩展」是 AI 能力的统一入口：把**插件、技能、MCP 服务器、知识库、连接器**五类放在同一张列表里，按类型筛选、按关键词搜索，省得在设置里来回翻。

入口：**设置 → AI 配置 → 扩展**。

> 这一页只做「看 + 转发」。插件的启停与卸载就地完成，其余类型的安装、编辑、删除仍在各自的原页——列表里每行右下角的「管理」按钮会跳过去，选中某个类型时列表底部也会多出一条同名入口。

## 五类分别是什么

| 类型 | 是什么 | 要不要额外权限 |
| --- | --- | --- |
| 插件 | 跑在容器里的扩展服务（`.txplugin` 包），App 只负责装、起、停、卸 | 需要容器可用（首次会自动安装容器）；常驻服务占端口 |
| 技能 | 一份 `SKILL.md` 指南，AI 遇到相关任务时才加载 | 不需要，纯本地文件 |
| MCP 服务器 | 接入的外部工具服务（HTTP 或本地 stdio） | 远程 HTTP 可能需要密钥 / OAuth 授权，在 MCP 页配 |
| 知识库 | 一个远端 Markdown 仓库，同步到本地供 `knowledge_search` 检索 | 不需要；出厂源不可删，自己加的源可在知识库页移除 |
| 连接器 | 内置的 MCP 接入模板（含鉴权方式），一键接成工具 | 接入后按服务要求授权（OAuth / 密钥） |

## 状态怎么读

列表里每条右侧有一个状态词，含义按类型略有不同：

- **运行中** — 插件的常驻服务正在跑（端口探测通过）。卡片上有「停止」。
- **已安装** — 已经装好了。插件在此状态下会显示「启动」；技能、知识库、连接器则不需要再做什么。
- **可更新** — 市场里的版本比本地新，市场条目上会出现「更新」。
- **可用** — 还没有装（市场里可安装的插件），或者是不带「安装」概念的出厂知识库源。
- **失败** — 插件上一次启动失败，卡片副标题会带出原因。

每种类型在卡片副标题里都写了一句说明，比如「内置接入模板，无需安装」「出厂源，始终启用、不可删除」，照那句话读就不会误以为连接器也需要装。

## 插件市场

在「扩展」页把类型切到**插件**，下方会出现「插件市场」——列出源里所有可安装的插件（名称、版本、作者、描述），点「安装」即下载并装进容器；已经装过的会显示「已安装」，有新版则变成「更新」。

- 市场列表靠**索引文件**驱动：源仓库里放一份 JSON（条目自带下载地址），App 拉下来照着装。
- 源清单是 `data/plugins.json`（随 App 打包的兜底叫 `plugins-market.json`，内容一致），App 启动时会对账更新一份。**加源、换地址只改仓库里那个 JSON，不必发版。**
- 拉不到和源里确实没有是两回事，列表会分别提示「没取到，稍后重试」与「源里暂无插件」；点右上角「刷新」可重试。

想装自己的插件包（本地 `.txplugin` 文件），到插件原页用「导入插件包」，扩展页的「管理」可以跳过去。

## 自己做插件包

`.txplugin` 就是一个 zip，里面只有两样东西：根目录的 `manifest.json` 和 `payload/` 目录。`payload/` 里的文件会被原样解到容器的插件目录下，安装、启动都按清单里的命令来。

```
my-tool.txplugin
├── manifest.json
└── payload/
    ├── bin/
    │   └── mcp-server
    └── data/
```

一份能跑的最小清单：

```json
{
  "schemaVersion": 1,
  "id": "my-tool",
  "name": "我的工具",
  "version": "1.0.0",
  "description": "本地小工具",
  "publisher": "我",
  "launchType": "service",
  "servicePort": 8765,
  "servicePath": "/health",
  "installSteps": ["chmod +x payload/bin/mcp-server"],
  "launchCommand": "/root/.aharou/plugins/my-tool/payload/bin/mcp-server",
  "verifyCommand": "test -x payload/bin/mcp-server",
  "mcpEntry": "payload/bin/mcp-server",
  "mcpArgs": ["--mcp"]
}
```

常用字段：

| 字段 | 作用 |
| --- | --- |
| `id` | 目录名，只能用字母、数字、点、下划线和连字符，**不能带 `../`** |
| `servicePort` / `servicePath` | 填了就是常驻服务，App 会等你这个端口能访问才算启动成功；不填就是纯工具型插件 |
| `installSteps` | 安装时逐条执行的命令，任一条非零退出就判安装失败 |
| `launchCommand` | 启动命令。**相对名只在插件目录的 `bin/` 下找**，放在 `payload/bin/` 里的要写绝对路径（如上例），或者在 `installSteps` 里软链到 PATH 后只写命令名 |
| `verifyCommand` | 安装后自检，随便跑一条能证明装好的命令 |
| `mcpEntry` / `mcpArgs` | 填了之后这个插件会作为 MCP 服务器暴露给 AI，插件里的工具直接变成 AI 可调用的能力 |
| `integrity` | 形如 `{"bin/mcp-server": "<sha256>"}`，只在装了之后对不上时提示，不会阻止安装 |

几个容易踩的点：

- **`payload/` 是唯一会被解出来的目录**，包里的其它文件一律忽略。
- 安装脚本里可以用 `$TAIXU_PLUGIN_PAYLOAD`（指向 `payload/`）和 `$TAIXU_TOOL_DIR`（指向插件根目录）。
- 重启 App 后，**上次处于「运行中」的插件会被自动拉起**；启动失败连续几次后按指数退避重试，不会每半分钟撞一次。
- 插件处于「运行中」时，卡片上会多一个**「打开管理页」**，用系统浏览器打开 `http://127.0.0.1:<端口><路径>`。
