# 记忆与项目规则

本章介绍自动记忆与项目规则两项能力，用于保持 AI 跨会话的上下文连续性与项目一致性。

## 自动记忆

自动记忆是 AI 自行维护的长期知识库。对话中形成的项目约定、用户偏好与架构决策，AI 会自动记录并在后续会话中复用。

### 作用域

| 作用域 | 说明 | 存储位置 |
| --- | --- | --- |
| 全局 | 跨项目通用的个人偏好 | `~/.aharou/memory/` |
| 项目 | 当前项目专属的约定与经验 | 本地模式：`<项目根>/.aharou/memory/`；远程 SSH 模式：`~/.aharou/memory/projects/<项目名>-<标识哈希>/` |

项目记忆在远程模式下存储于手机本地，并按「项目名 + 服务器标识」隔离，不受容器重置影响。

### 记忆文件

每条记忆是一个 Markdown 文件，由 YAML frontmatter 与正文组成：

```markdown
---
name: conventions
description: 项目代码规范与命名约定
type: workflow
keywords: [命名, 代码规范, 提交规范]
---
（正文）
```

| frontmatter 字段 | 说明 |
| --- | --- |
| `name` | 记忆名称，同时用作文件名 |
| `description` | 一句话摘要，注入到每次会话的提示词清单中 |
| `type` | 分类，决定是否常驻提示词清单，见下表 |
| `keywords` | 检索关键词列表，仅供 `action=search` 匹配，不进清单 |

**`type` 取值：**

| 类型 | 说明 | 是否注入清单 |
| --- | --- | --- |
| `identity` | 身份与长期约定（CORE / GLOBAL 类） | 是，永远保留 |
| `preference` | 用户偏好 | 是 |
| `workflow` | 做事方式与流程约定 | 是 |
| `fact` | 一般事实（默认值） | 是 |
| `event` | 一次性事件（某次测试结果、某天的排查记录） | 否，只留档 |

`event` 类记忆不进提示词清单，需要时通过 `action=search` 或 `action=read` 取回。超过 180 天未修改的普通记忆也会从清单中淡出（文件仍保留，仍可读取）。

### 生效方式

会话开始时，系统注入符合条件的记忆索引（名称、作用域与描述），而不是全部记忆正文。主代理、子代理及自定义提示词中的 <code v-pre>{{AICODE_MEMORY}}</code> 使用同一份索引，总预算为 **8,000 字符**，包括分组标题、名称、作用域说明、描述、换行和省略提示；同一份提示词中的记忆索引不会重复注入。

索引先为核心档案与身份类记忆分配预算，展示时尽量保持原有的全局 / 项目分组及条目排序。预算不足时省略整条索引，并显示省略提示。这个预算只控制摘要清单，不裁剪核心记忆正文、人格（Soul）、项目规则或静态规则，也不修改或删除记忆文件。

索引未注入不表示记忆丢失：`memory(action=list)` 仍可获得完整清单，再通过 `memory(action=read, name=..., scope=...)` 读取正文；事件类、长期未修改或因预算省略的条目同样可以按需查阅。

### memory 工具

| 参数 | 说明 |
| --- | --- |
| `action` | `read` / `save` / `edit` / `delete` / `list` / `search` / `log` / `fact` / `mindstream` / `core` |
| `name` | 记忆名称（即文件名）；`search` 时作为 `query` 的备用参数 |
| `description` | 摘要，`save` 时必填 |
| `content` | 正文（Markdown），`save` 时必填 |
| `edits` | 局部编辑列表，语义与编辑文件一致 |
| `scope` | `project`（默认）或 `global` |
| `query` | 搜索关键词，`search` 时使用 |

`action=search` 按关键词检索记忆，依次在 `keywords`（权重最高）、名称与描述、正文中打分，返回最多 8 条匹配结果的摘要行。找到目标后再用 `action=read` 取完整正文，避免把上下文撑满。

除通用的读写改删与检索，还有四个「持续记录」用的动作：

| 动作 | 用途 |
| --- | --- |
| `log` | 追加每日日志——按天归档的流水笔记 |
| `fact` | 追加一条事实，进结构化的事实库 |
| `mindstream` | 追加心流——记录当下的想法与情绪，不求结论 |
| `core` | 读 / 写核心档案（一事一条，每次对话都会自动携带） |

未指定作用域时，同名记忆按项目级优先展示；明确指定作用域时，只读取该作用域。设置页分别管理全局与项目条目，同名条目不会互相隐藏。更新既有记忆时建议使用 `edit` 局部编辑；涉及踩坑经验的内容，应在验证根因后记录。

### 编辑与待确认记忆

在**设置 → 记忆**中点开条目可编辑摘要与正文；编辑只改这两项，原有分类、关键词与过期时间都会保留。保存成功后才返回列表——失败时页面保留草稿并提示原因，请检查存储权限和可用空间后重试，已输入的内容不会丢失。

标为「待确认」的条目存在尚未解决的争议。普通「保存」只修改内容，不代表确认；核对相关说法后，可点击「确认此条并保存」。确认只作用于当前条目，其他冲突条目仍需分别处理。待确认内容不能当作已确认的长期约定直接执行。

### 立即蒸馏

蒸馏是把近期每日日志提炼成长期要点并追加到 `GLOBAL.md` 的过程，默认每 7 天自动执行一次。

在**设置 → 记忆**页面可以找到「立即蒸馏」按钮，点击后忽略 7 天间隔立即执行一次。完成后界面会提示「蒸馏完成，已写入 GLOBAL.md」；如果近期日志没有可提炼的新内容，或当前会话未配置 AI 供应商，则提示「没有新的可提炼内容」。

蒸馏需要调用 AI 模型，请确保已在设置中配置好供应商与模型。

### 检索测试

记忆能不能被召回，取决于摘要和关键词里有没有写上你平时会说的那些词。**设置 → 记忆 → 检索测试**就是用来提前验证这件事的。

在输入框里填一句话或一个域名（例如「帮我改一下 PRoot 的启动流程」），点「测试」，下面会按注入顺序列出最多 10 条记忆，每条显示：

- 记忆名称与作用域（全局 / 项目）；
- 摘要；
- 命中了哪个字段：关键词、名称还是摘要。三条都没命中时标为「未命中字段」。

命中说明这句话能把这条记忆排到注入清单前面；三条都没命中的条目只是因为清单还没满、按最近修改时间兜底排进来，对这句话没有实际帮助。

如果整句输入一条都没命中，页面会直接提示——这时请打开相关记忆，把这句话里的关键实体（域名、模块名、专有名词）补进摘要或关键词，再回来重测。

检索测试是只读的：它按当前工作区的注入清单现算一遍，不会写入、修改或删除任何记忆，也不会影响之后的排序结果。

### 最近记忆操作

**设置 → 记忆**页面底部列出最近 20 次记忆写入，每条显示动作、涉及的记忆名与时间。

它回答的是「记忆怎么又变了」「怎么没写进去」这类问题：一条记忆是被覆盖、被判定重复而跳过，还是整理进程压根没跑，光看记忆文件是看不出来的。

| 动作 | 含义 |
| --- | --- |
| 新建 / 保存 | 手动保存了一条新记忆，或覆盖了同名记忆的旧内容 |
| 编辑 / 删除 | 局部修改了正文，或删除了记忆 |
| 归档 | 旧版本被移入记忆目录的 `archive/` 子目录 |
| 合并 / 冲突 / 跳过 | 会话结束后自动整理的判定结果：并入已有记忆、保留矛盾说法等待确认、判定重复而不写入 |

归档文件不参与提示词注入，也不会被 `action=search` 命中；需要时按文件名直接读取。写入记录保留最近 300 条，超过后自动丢弃最旧的。

### 多设备同步

在**设置 → 记忆 → 同步到自己的仓库**填一个自己的 Git 仓库地址（私有仓库还需填访问令牌），就能把本机记忆同步进去。点「立即同步」马上推一次；打开「自动同步」后会在后台定期推送。同一个仓库可以同时安放多台设备、多个项目的记忆。

自动同步交给系统的后台调度执行，**省电模式或厂商的后台限制可能把它推迟**（有时会晚好几个周期）。页面上的「上次同步时间」长时间不更新时，点「立即同步」就能马上跑一次。AI 整理完记忆后也可以自己触发一次这个动作，不用等下一轮周期。

同步做两件事：把本机的全局记忆与各项目记忆收进这个仓库，同时把其他设备推上来、本机还没有或没改动的记忆补回本机。

同一条记忆在两台设备上都改过时：

- 只有远端改过、本机没动，本机这条会更新为远端版本；
- 本机与远端都改过，则**保留本机版本继续推送，远端版本另存进这条记忆的归档**（在「归档」区查看和恢复），不会静默覆盖本机的改动。

每次同步结束后，页面会列出本次结果：收进仓库的条目数、冲突条目数，以及「疑似在其他设备删除」的条目数。**这只是提示，同步不会自动删除本机任何记忆**——某条记忆在同步前还在、这次本机与仓库里都找不到时，它才会出现在这份清单里；确认不再需要时请自行到记忆列表删除。

让 AI 同步（`memory` 工具的 `sync`）时，它拿到的口径与页面一致，但更细：会列出**具体收上了哪些文件**（超量只列前 20 个）、以及「内容未变跳过」「本机有改动保留本机」「写入失败」的分类计数与失败原因。

## 哪些约定真的进了上下文

记忆不是写得越多就越“记得”：标为 `identity` 类的约定会常驻系统提示，但有单条与总量上限，超出的条目只保留名字和摘要，正文不会自动进上下文。

让 AI 调 `memory` 的 `stats`，除了使用统计与冷记忆清单，末尾会多一段「常驻正文预算」：identity 共几条、实际常驻几条、**哪些被预算挤出以及原因**（单条超限 / 总量被前面的条目占满）。被挤出的条目要用 `read` 取全文才会回到模型眼前。

## 项目规则

项目根目录下的 `AGENTS.md` 用于声明项目专属规则、架构约束与构建指南，是 AI 遵循的最高优先级约定；不存在 `AGENTS.md` 时回退读取 `CLAUDE.md`。

### 生效方式

规则文件在会话开始时自动加载，无需手动配置；内容超过 32,000 字符时将被截断。

### 自定义加载约定

项目规则的加载约定对应提示词片段 `15-project-rules.md`，可通过 `~/.aharou/prompts.custom/15-project-rules.md` 覆盖，见[自定义提示词](/guide/custom-prompts)。
