# 跨设备协作

「设置 → 更多 → 跨设备协作」让两台装了 Aharou 的设备互相执行操作：**本机开启协作后，配对过的另一台设备可以请求本机读文件、写文件、执行命令、截图**。默认关闭。

两种用法：

- **同一局域网**：最省事，两台设备连同一个 WiFi 就能配对。
- **跨网络协助**（人不在同一个地方）：打开「允许公网对端」，再把页面给出的**协助地址**发给对方。前提是双方都有可用的 IPv6（手机在 5G 与多数宽带下都有）。

> 跨网络这条走的是两台设备**直连**，不经过任何中转服务器。

## 开启与配置

| 项 | 说明 |
| --- | --- |
| 开启跨设备协作 | 启动本机服务。**关闭只停服务、不清授权**——下次打开，之前配过的设备仍能连 |
| 设备名 | 对端看到的名称；留空用机型名 |
| 端口 | 服务监听的端口（1024–65535） |
| 远端动作每次都需确认 | 默认**关闭**：协助时弹窗往往没人点。打开后每个远端动作都要在本机点一次「允许」 |
| 允许公网对端 | 默认**关闭**（只接受同一局域网）。打开后才接受跨网络来源——此时能进门的就只剩配对码了 |

## 把本机交给别人协助

1. 打开「开启跨设备协作」。
2. 点「生成配对码」，页面会显示 **6 位码**与**协助地址**（可能有多条，跨网络的排在最前）。
3. 点「复制」，把这串发给协助你的人。
4. 配对码**一直有效**，配对成功一次后会自动换成一枚新的。

## 接受别人的协助

1. 让对方按上面步骤把「协助地址 + 6 位码」发给你。
2. 本机进「跨设备协作 → 接受协助 → 连接到另一台设备」，填入地址与 6 位码。
3. 配对成功后，对端会自动登记成一个 MCP 服务器，之后就能读写它的文件、执行命令、看它的屏幕。

## 传文件

除了逐段读写的 `read_file` / `write_file`，还有两条专门搬**整文件**的路子。它们走原生 HTTP 流：
**二进制安全、不设大小上限**（不受 MCP 那 256 KB 正文限制），适合 APK、图片、压缩包。

| 动作 | 作用 |
| --- | --- |
| `fetch_file {path}` | 取回本机的文件 → 返回一条一次性**下载链接** |
| `push_file {path}` | 往本机放一个文件 → 返回一条一次性**上传链接** |

拿到链接后，用任何 HTTP 客户端操作即可（地址用你连接本机时用的那个）：

```bash
curl -o app.apk "http://<对方地址>:47822/file/<票据>"
curl --data-binary @photo.jpg "http://<对方地址>:47822/upload/<票据>"
```

两点提醒：

- 链接是**一次性**的（用过即废）、**15 分钟**内有效，且只对签发时那一个路径有效——就算链接被别人看到，能做的也只是把那个文件取走、或覆盖那一个文件。
- 路径同样走越界校验（只允许工作区 / 容器 rootfs / AI 配置 / 记忆 / 共享区之内），越界直接拒。
- 上传大文件耗时较长（比如 1 GB 在直连下大约几分钟），中途断线需要重传。

## 授权与撤销

- **开着跨设备协作时，本机不再弹审批**：协助你的人往往不在手机跟前，逐次弹窗等于把功能废掉。关掉开关即恢复逐次询问。
- 想让远端动作恢复「每次都问」，打开「远端动作每次都需确认」。
- 灾难性操作（如 `rm -rf` 这类删除）**不走审批，而是直接拒绝**——协作模式下同样被拒。
- 「已授权设备」列出每台设备的授权时间与最近活跃；**左滑**可撤销，撤销后该设备需重新配对。

## 安全提示

::: warning
- 服务开启后，界面上的**配对码就是唯一门槛**，别往群里或公开场合发。
- 打开「允许公网对端」后，互联网上能连到这个端口的人都能尝试配对（有失败次数节流兜底）。
- 配对成功后对方持有的是**长期令牌**，可读写文件、执行命令、截屏。协助结束请到「已授权设备」里撤销，或直接关掉开关。
:::

## 出错怎么办

- **对端连不上**：确认地址与端口填对、对方开关已打开；跨网络时确认双方都有 IPv6——在对方页面的「协助地址」里能看到带方括号的地址就说明有。
- **配对失败**：确认 6 位码没抄错（码里不含 `0/O/1/I`）；提示「尝试次数过多」就等一分钟再试。
- **动作被拒**：命中灾难性规则的命令属硬拒绝，改成更精确的命令；其它情况看本机弹窗或通知栏。
