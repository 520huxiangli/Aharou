# 跨设备协作

「设置 → 更多 → 跨设备协作」让两台装了 Aharou 的设备互相执行操作：**本机开启协作后，配对过的另一台设备可以请求本机读文件、写文件、执行命令、截图、在影子屏里驱动屏幕，也可以给本机指定的工作区/会话传一条消息**。默认关闭；配对一次即双向互通（见〈一次配对即互通〉）。

两种用法：

- **同一局域网**：最省事，两台设备连同一个 WiFi 就能配对。
- **跨网络协助**（人不在同一个地方）：打开「允许公网对端」，再把页面给出的**协助地址**发给对方。前提是双方都有可用的 IPv6（手机在 5G 与多数宽带下都有）。

> 跨网络这条走的是两台设备**直连**，不经过任何中转服务器。

## 开启与配置

| 项 | 说明 |
| --- | --- |
| 开启跨设备协作 | 启动本机服务。**关闭只停服务、不清授权**——下次打开，之前配过的设备仍能连 |
| 设备名 | 对端看到的名称；留空用机型名 |
| 端口 | 服务监听的端口（1024–65535） |
| 远端动作每次都需确认 | 默认**关闭**：协助时弹窗往往没人点。打开后每个远端动作都要在本机点一次「允许」 |
| 允许公网对端 | 默认**关闭**（只接受同一局域网）。打开后才接受跨网络来源——此时能进门的就只剩配对码了 |
| 一次配对即互通 | 默认**开启**：对方用配对码连上本机后，本机顺带回连一次、把对方也登记成本机的 MCP 服务器——只配一次就双向互通。关掉后每次配对只开通一个方向 |

## 把本机交给别人协助

1. 打开「开启跨设备协作」。
2. 点「生成配对码」，页面会显示 **6 位码**与**协助地址**（可能有多条，跨网络的排在最前）。
3. 点「复制」，把这串发给协助你的人。
4. 配对码**一直有效**，配对成功一次后会自动换成一枚新的。

## 接受别人的协助

1. 让对方按上面步骤把「协助地址 + 6 位码」发给你。
2. 本机进「跨设备协作 → 接受协助 → 连接到另一台设备」，填入地址与 6 位码。
3. 配对成功后，对端会自动登记成一个 MCP 服务器，之后就能读写它的文件、执行命令、看它的屏幕；默认还会顺带把本机也登记到对端（见〈一次配对即互通〉）。

## 一次配对即互通

默认开启。开启后**只配对一次就双向互通**：对方用你给的配对码连上本机时，本机会顺着这次连接回连对方一次，把对方也登记成本机的一个 MCP 服务器（在「设置 → AI 配置 → MCP」里会多出一条），于是对面能操作本机、本机也能操作对面。

这条回连只认对方的**实际来源地址**——对方配对时填进来的地址不采用，所以没法拿「配对」当跳板让本机去打别的机器。

想只开通一个方向，就到「跨设备协作」里把「一次配对即互通」关掉：

- 关掉后每次配对只开通一个方向——对方能操作本机，本机不会自动登记对方。要反向操作，在本机「接受协助」里再配一次即可。
- 回连失败（网络不通、对方端口不通等）时也只开通单一方向：失败只影响反向那一段，本次配对照常成功，之后手动反向配对就能补上。

## 返回与提示

每个动作的返回都是「结果 + 一行提示」，失败时尤其明显：

- **成功时**：结果照旧；若还有明确的下一步（例如 `write_file` 成功后要复核），末尾多一行 `hint: …`；
- **失败时**：正文前面带错误码（形如 `[STALE_FILE] …`），末尾的 hint 直接给出**该怎么改**——路径越界会列出允许的根、文件被本机改过会提示先重读、没获批会说清是协作开关没开还是该改用 `send_message`。

这些提示是给调用方（多半是另一个 AI）看的，好让它一次就能改对，而不是换几个参数反复撞同一条错路。

## 传文件

除了逐段读写的 `read_file` / `write_file`，还有两条专门搬**整文件**的路子。它们走原生 HTTP 流：
**二进制安全、不设大小上限**（不受 MCP 那 256 KB 正文限制），适合 APK、图片、压缩包。

| 动作 | 作用 |
| --- | --- |
| `fetch_file {path}` | 取回本机的文件 → 返回一条一次性**下载链接** |
| `push_file {path}` | 往本机放一个文件 → 返回一条一次性**上传链接** |

拿到链接后，用任何 HTTP 客户端操作即可（地址用你连接本机时用的那个）：

```bash
curl -o app.apk "http://<对方地址>:47822/file/<票据>"
curl --data-binary @photo.jpg "http://<对方地址>:47822/upload/<票据>"
```

两点提醒：

- 链接是**一次性**的（用过即废）、**15 分钟**内有效，且只对签发时那一个路径有效——就算链接被别人看到，能做的也只是把那个文件取走、或覆盖那一个文件。
- 路径同样走越界校验（只允许工作区 / 容器 rootfs / AI 配置 / 记忆 / 共享区之内），越界直接拒。
- 上传大文件耗时较长（比如 1 GB 在直连下大约几分钟），中途断线需要重传。

## 给对端传话

`send_message {text, workspace?, session_id?}` 把一段纯文本**传进对端的会话**——它不写文件：消息直接出现在对方的聊天里，并在对方手机上弹一条通知（标题是「来自 <设备名> 的消息」）。

- 正文是纯文本，建议一两句话以内。传进来的消息上方会标出「来自『对方设备名』的传话」，一眼能看出不是本机 AI 说的。
- 这条消息只作展示，**不进对方的 AI 上下文**——对方的 AI 不会把自己没说过的内容当成自己说过的话。
- 对方开着「远端动作每次都需确认」时，这条传话也要在对方手机上点一次「允许」才送达。

### 指定投给哪个工作区/会话

默认投进对端**当前工作区最近活跃的会话**；要投到别处就带两个可选参数：

- `workspace`：目标工作区的目录名，如 `小染-076a5120`。唯一时也可以只写前半段（`小染`）；命中多个会报错并列出候选，让你写全名。
- `session_id`：目标会话 id。只给 `session_id` 时以该会话所属工作区为准。

返回里带 `workspace`、`session_id`、`session_title`，一眼能核对其实际投到了哪里。**找不到工作区或会话会直接报错**（`WORKSPACE_NOT_FOUND` / `WORKSPACE_AMBIGUOUS` / `SESSION_NOT_FOUND` / `SESSION_WORKSPACE_MISMATCH`），不会静默退回当前会话。工作区参数与 `ask_ai` 完全一致。

## 跟对端的 AI 对话

`ask_ai {text, timeout_seconds?, workspace?, session_id?}` 把一段提问发给**对端的 AI**：作为用户消息进入目标会话、触发一轮，并把回复正文原样返回。默认最多等 60 秒（上限 100），超时则返回「已投递，稍后到本机会话里看」。`workspace` / `session_id` 的含义与 `send_message` 相同，返回里同样带实际投递到的 `workspace` 与 `session_id`。

它跟 `send_message` 是一对，别混：

| | 给谁看 | 进 AI 上下文 | 有回复 |
| --- | --- | --- | --- |
| `send_message` | 对端的**人** | 否 | 无 |
| `ask_ai` | 对端的**AI** | 是 | 有 |

**要它真能问出答案，得先在本机授权**：「跨设备协作 → 允许已配对设备向本机 AI 提问」（默认关）。关闭时 `ask_ai` 直接返回「本机没有开放这项授权」；打开后，提问会**以本机用户的口吻**投进会话，本机 AI 会当成用户说的来回答。

这是有意的取舍：等于让已配对设备借本机 AI 办事（它们本来就能 `shell` / `write_file`，这里多出来的是「AI 被指挥做你没打算的事」）；工具调用仍走本机权限引擎，该审批的照旧。

即便打开了，本机 AI 仍可能挑活或拒绕——它是模型判断，不是接口。**别把这条通道当成可靠的执行通道**；要确定地把活儿办掉，用 `shell` / `write_file`，或者 `send_message` 把话交给人。

## 读对端的应用日志

`read_logs` 读**对端 Aharou 的应用日志**。这是拿到它的唯一途径：日志落在应用的私有目录，容器里看不见——就算连着对端的终端也读不到；而读它的人是 App 自己，不需要 root 或 Shizuku。

| 参数 | 说明 |
| --- | --- |
| `date` | 日期 `yyyy-MM-dd`，缺省今天；日志只保留最近 7 天 |
| `query` | 关键词过滤（大小写不敏感），比如「还原」「压缩」 |
| `limit` | 最多返回行数，默认 200，上限 2000 |

典型用法：对方说「回退把几天的代码搞丢了」，你直接读他那边的日志、搜「还原开始」，就能看到那次回退涉及几个检查点、处理了几个文件、哪些被跳过——不必让他来回截图。

这是只读动作，不改任何东西；授权与其它动作一致（开着协作时免逐次确认，关掉开关则逐次询问）。

## 驱动对端的屏幕

`ui {action, …}` 在**影子屏**里操作对端设备：`start` 拉起影子屏、`launch` 启动 App、`shot` 截图（传 `ocr=true` 只回文字）、`tap` / `swipe` / `key` 触控、`type` 输入文字。

影子屏是宿主上的无头虚拟显示屏，所以这些操作**不会打断对方正在用的主屏**，迷惑感小——但也意味着对方「看不到」你在点什么（本机日志里留痕，可用 `read_logs` 查）。

只支持这七个操作。`stop` 与 `task`（把「看屏→决策→动作」的多步循环交给手机操作子代理）**不开放给远端**——后者等于给远端开一台无限调用对方 AI 的机器；而 `start` 必须开放，否则 `launch` / `shot` 都跑不起来。

两点前提：

- 对端需要 root 或 Shizuku 就绪（影子屏依赖它），没就绪时返回里会说明；
- 影子屏没启动过时，先 `ui action=start` 拉起来，再 `ui action=launch` 起目标 App，然后才能 tap / type。

带 `label` 的 `tap` / `type` 走对端同一套敏感词风控：命中「确认支付」这类词时，**即使协作开着也会逐次确认、且不可记忆**。

## 授权与撤销

- **开着跨设备协作时，本机不再弹审批**：协助你的人往往不在手机跟前，逐次弹窗等于把功能废掉。关掉开关即恢复逐次询问。
- 想让远端动作恢复「每次都问」，打开「远端动作每次都需确认」。
- 灾难性操作（如 `rm -rf` 这类删除）**不走审批，而是直接拒绝**——协作模式下同样被拒。
- 「已授权设备」列出每台设备的授权时间与最近活跃；**左滑**可撤销，撤销后该设备需重新配对。

## 安全提示

::: warning
- 服务开启后，界面上的**配对码就是唯一门槛**，别往群里或公开场合发。
- 打开「允许公网对端」后，互联网上能连到这个端口的人都能尝试配对（有失败次数节流兜底）。
- 配对成功后对方持有的是**长期令牌**，可读写文件、执行命令、截屏、给本机工作区投消息。协助结束请到「已授权设备」里撤销，或直接关掉开关。
- 开着「一次配对即互通」时，配对成功会让**双方各多一条授权**（本机也拿到对对方的令牌）。只想给对方开权限就把它关掉。
:::

## 出错怎么办

- **对端连不上**：确认地址与端口填对、对方开关已打开；跨网络时确认双方都有 IPv6——在对方页面的「协助地址」里能看到带方括号的地址就说明有。
- **配对失败**：确认 6 位码没抄错（码里不含 `0/O/1/I`）；提示「尝试次数过多」就等一分钟再试。
- **动作被拒**：命中灾难性规则的命令属硬拒绝，改成更精确的命令；其它情况看本机弹窗或通知栏。
- **只通了一个方向**：配对成功后一方操作不了另一方，多半是自动回连没成功。确认两台设备网络互通后，在「接受协助」里手动反向配一次即可。
