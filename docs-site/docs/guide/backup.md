# 备份与还原

「设置 → 更多 → 备份与还原」可以把应用配置、聊天记录、记忆与灵魂和工作区文件导出成一个加密压缩包，也能从备份还原回来。

## 导出

页面上方勾选要导出的范围，共八项：AI 供应商、连接与同步、聊天记录、MCP 服务器、授权规则、应用设置、工作区文件、记忆与灵魂。勾选状态会记住，下次进来沿用。

其中的**记忆与灵魂**打包 `aharou-global/memory` 下的全部文件（`SOUL.md`、核心档案、全局记忆、每日日志、facts 等）。

其中**工作区文件默认关闭**，需要时手动打开。它会打包所有本地模式的内部工作区文件，包含 `.git` 目录，所以仓库历史和未推送的提交都能完整还原。通过「添加外部工作区」加进来的目录属于你设备上的原始目录，不会被打包。排除规则是各工作区自己的 `.gitignore` 加上同步功能的默认忽略清单（`node_modules`、`build`、`dist` 等），符号链接不备份。

::: tip 代码优先用 Git 备份
Git 仓库本身就完整保存了代码和历史，这里的导出更适合作为额外的备用手段，而不是主要的代码备份方式。
:::

点「导出备份」后会弹窗设置口令：

- **填了口令**：用 AES-GCM 加密。
- **留空**：输出明文 tar.gz。

导出的包里含 API Key 等凭据，通过系统文件选择器保存到你指定的位置。

::: danger 务必牢记加密口令
加密备份在遗失口令时无法解密恢复，没有任何后门或找回途径。
:::

## 导入

从备份文件还原，采用**合并方式**，不会清除现有数据。需要输入对应的口令，未加密的备份留空即可。

只有导出时勾选了「应用设置」的备份才会恢复主题、配色和偏好设置。单独导出的聊天记录，以及未勾选「应用设置」的备份，导入后会保留当前应用设置。

如果备份里含工作区文件，会先弹出「恢复工作区」选择弹窗，列出备份中的每个工作区（名称和文件数），你可以勾选要恢复哪些。

::: warning 恢复工作区会直接覆盖
勾选的工作区会覆盖本地同名工作区里的文件，且无法撤销。本地没有同名工作区时会自动新建一个再写入，所以换新设备或重装后不会丢数据。远程模式的工作区（文件在服务器上）不参与还原。
:::

导入完成后会显示还原数据的汇总清单：供应商、远程连接、远程挂载、聊天会话、聊天消息、待办项、MCP 服务器、全局授权规则、工作区文件、记忆文件各恢复了多少；若这次导入确实恢复了应用设置，末尾会再补一句「主题、保活、日志、识图、同步偏好已覆盖」。

加密备份只需在导入前解密校验一次，恢复时复用该结果，不会重复解密；过程中产生的临时文件在完成、取消、失败或退出导入后都会被清理。文件很大的备份在导入期间会临时占用一份应用内部存储，空间不足时会提示失败而不是写坏数据。

聊天会话会按备份时的所属工作区归位：本地有同名工作区直接还原过去，没有同名工作区时会自动新建一个空工作区再挂入会话（与「恢复工作区」自动新建的逻辑一致），换设备或重装后各工作区的会话不会挤到同一处。

## 一点说明

备份口令只作用于导出的备份文件本身。应用内部存储的 API Key、连接密码、SSH 私钥等敏感配置另由系统密钥库（Android Keystore）加密保存，与备份口令相互独立；换设备时请通过备份导入迁移，直接拷贝应用数据目录会因密钥不匹配而无法解密。

## 网络备份

除了导出成本地文件，还能把备份直接传到网络存储。切换到「网络」标签页即可配置目标，支持 **WebDAV** 与 **S3 对象存储** 两种。

点「添加备份目标」，选择类型后填写：

- **WebDAV**：服务地址（如 `https://dav.example.com/remote.php/dav/files/你的用户名/`）、可选的目录前缀、用户名与密码。
- **S3**：服务地址（自建服务如 MinIO / R2 时填写，用 AWS 官方存储则留空）、存储桶、区域、Access Key、Secret Key，以及可选的会话令牌与对象键前缀。自建服务通常需要打开「路径式寻址」。

保存后，目标会出现在列表里。点一行进入远端备份管理：

- **测试连接**（行尾闪电图标）：检查地址与凭据是否正确。
- **刷新**：重新拉取远端已有备份。
- **上传备份**：把当前的本地备份上传上去。上传**必须设置口令**——备份文件里是解密后的 API Key 与 SSH 凭据，不加密等于把它们明文传到远端。
- **恢复**：把远端某个备份下载并还原，流程与本地导入完全一致（含工作区勾选与冲突处置弹窗）。
- **删除**：删除远端上的某个备份文件。

目标列表支持左滑删除目标本身。编辑目标点行尾铅笔图标。

::: tip 凭据的安全
目标里的密码、Secret Key 等凭据由系统密钥库加密后保存在本机，不会以明文形式落库。**这些目标本身不随备份包迁移**：换设备后需要在新的设备上重新添加一次网络备份目标，再用它去恢复远端备份。
:::

::: warning 网络异常
地址、端口、凭据错误或网络不通都会导致测试连接与上传/恢复失败，页面会给出对应提示（如认证失败、目标不存在、网络连接失败）。请逐一核对后再试。
:::
