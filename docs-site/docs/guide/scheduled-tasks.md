# 自动化任务

::: tip 版本说明
自动化任务即原来的「定时任务」，从 v2.8.2 起提供；「每天定时」「只跑一次」与事件触发（收到通知 / 电量变化 / 网络变化 / 开机）都是后来加的。
:::

自动化任务让 AI **按你定的时间、或发生的事自己干活**，不用每次开口。适合「每天早上提醒我今天的日程」「每小时巡检一遍某件事」「微信来消息就提醒我」这类动作。

## 触发方式

它有两种活法：**到点就跑**，和**等到某件事发生再跑**。

| 触发方式 | 什么时候跑 | 适合 | 延迟与前提 |
| --- | --- | --- | --- |
| 到点 | 到你设定的时间就跑 | 提醒、巡检、每日汇总 | 选定时刻走系统精确闹钟；周期任务由后台调度，时间上会有几分钟浮动 |
| 收到通知 | 手机收到通知时跑，可只认某个应用 | 「微信来消息就提醒我」「别漏了重要通知」 | 要你先在系统里勾选**通知使用权**，没勾就收不到；通知正文有时会被应用藏起来 |
| 电量变化 | 电量降到某个百分比、或插上充电时跑 | 「电量掉到 20% 提醒我充电」「一插上电就整理今天的照片」 | 靠**每 15 分钟一次**的后台检查比对，最多晚 15 分钟，别当实时用 |
| 网络变化 | 连上或离开某个 WiFi 时跑 | 「到家（连上家里 WiFi）就播报今天日程」 | 同上，最多晚 15 分钟 |
| 开机 | 手机开机后跑 | 开机后自动做一轮检查 | 开机后由系统拉起，可能比开机时刻略晚 |

后四种统称**事件触发**：没有「下一次是什么时候」这回事，事件发生了才跑。

## 三种运行方式

只有**触发方式选「到点」**时，才需要挑运行方式：

| 运行方式 | 什么时候跑 | 适合 |
| --- | --- | --- |
| 按周期重复 | 每 N 分钟一次；**最短 15 分钟** | 巡检、整理这类周期性动作 |
| 每天定时 | 每天某个固定时刻（如 08:30） | 早晚提醒、每日汇总 |
| 只跑一次 | 在指定时刻跑一次，跑完自动停用 | 一次性提醒 |

选定时刻的任务（每天定时 / 只跑一次）走系统精确闹钟，准点触发；周期任务由系统后台调度，时间上会有几分钟浮动。

## 怎么用

进入「设置 → AI 配置 → 自动化任务」，点「＋」新建：

| 字段 | 说明 |
| --- | --- |
| 名称 | 任务名，会出现在任务列表、会话标题和通知里 |
| 指令 | 触发时发给 AI 的内容，等同于你在那个会话里打的一段话 |
| 触发方式 | 到点 / 收到通知 / 电量变化 / 网络变化 / 开机，见〈触发方式〉 |
| 运行方式、周期、每天的时刻、触发时间 | 触发方式选「到点」时才填 |
| 来源应用 / WiFi 名 / 电量阈值 / 插电触发 | 事件触发专用，按你选的触发方式出现 |
| 触发条件 | 生效时段、仅充电时、最低电量，见〈条件〉 |
| 防抖 | 事件触发专用，见〈防抖〉 |
| 运行位置 | **每次新建会话**：每次触发都开一个新会话（需要填工程工作区）；**指定会话**：固定在某一个已有会话里跑 |
| 运行上限 | 累计跑多少次后停止；填 `0` 表示不限 |
| 启用 | 关掉后不再触发，但配置保留 |

保存后任务立刻进入调度。列表里每一行会显示运行方式、下次运行时间（带倒计时）、已运行次数与上限，以及上一次的结果；开关可以随时启停，左滑删除。

## 条件

条件用来卡「这次该不该跑」。**条件不满足时，这一次就直接跳过**，不会排队等条件满足了再补跑。

| 条件 | 说明 |
| --- | --- |
| 生效时段 | 只在一天里的某段时间内才跑，可以跨午夜（例如夜里 23:00 到次日 06:00） |
| 仅充电时 | 没在充电就跳过；读不到充电状态也按不满足处理 |
| 最低电量 | 电量低于设定的百分比就跳过；读不到电量同样按不满足处理 |

三个都不设就是全天、随时可跑。条件对「到点」和事件触发都生效。

## 防抖

事件可能短时间连着来（一串通知、电量来回跳），防抖让**同一个任务在一个窗口里只跑一次**；默认 10 分钟，可以改，填 `0` 表示不防抖。

防抖只对事件触发有意义：到点任务的节奏由运行方式决定，本来就比窗口长。

## 到点会发生什么

- 触发后在目标会话里**跑一轮普通对话**——和你说一句话完全一样的链路，含工具调用、授权弹窗与上下文压缩。因此自动化任务也能用上所有工具（包括设备能力：建闹钟、查日程、发通知）。
- 准点靠**系统精确闹钟**，另有**每 15 分钟的后台兜底检查**：精确闹钟被系统拦掉或权限被收回时，仍会在下次检查里把该跑的任务捞起来。事件触发同样靠这轮检查兜底，这就是它「最多晚 15 分钟」的由来。
- 同一个任务在同一时刻**只会被触发一次**：多个触发撞上时只有一个能拿到。
- **不补跑**：迟到太久（周期任务超过一个周期，每天定时 / 只跑一次的任务超过两小时）这一次会被跳过并记下原因，只把时间推到下一次。记住提醒类任务晚了半天才响没有意义。
- 没有任何启用中的任务时，不会安排任何调度，也就不会为它唤醒进程。

## 把事件内容带进指令

事件触发时，指令里可以留占位符，触发时会替换成当时的值：

| 占位符 | 替换成 |
| --- | --- |
| `{{event.app}}` | 来源应用（包名） |
| `{{event.title}}` | 通知标题 |
| `{{event.text}}` | 通知正文 |
| `{{event.battery}}` | 当前电量，如 `37%` |
| `{{event.ssid}}` | 当前 WiFi 名 |
| `{{event.time}}` | 触发时刻，如 `2026-10-18 08:30` |

拿不到的值会写成「未知」。举个例子：触发方式选「收到通知」、来源应用填微信，指令写

> 微信来消息了，把内容一起发我：{{event.text}}

这样每次微信来通知，都会在会话里把那条消息的内容发给你。

## 为什么这次没跑

任务列表那一行会显示上一次的结果，含义如下：

| 显示 | 什么意思 | 该怎么办 |
| --- | --- | --- |
| 已派发 | 正常跑了一轮 | 不用管 |
| 上次错过未补跑 | 该跑的时候应用没在运行，迟到太久（周期任务超过一个周期、定时任务超过两小时），这一次放弃 | 属正常行为，下一次照常；想让时间更准，见〈需要开的权限〉 |
| 条件不满足 | 当时不满足你设的条件（不在时段内、没在充电、电量太低） | 检查条件设置；只是这一次没跑，下次满足照常 |
| 防抖中 | 上一次刚跑过，还在防抖窗口里 | 觉得太频繁就调大防抖；想每次都跑就填 `0` |
| 上一次还在跑 | 上一次刚派发出去没几分钟又来触发了，为避免重复执行跳过 | 一般不用管；事件太密集就把防抖调大 |

想看更细的原因，去「更多 → 日志」里按任务名找。

## 需要开的权限

- **精确闹钟**：Android 12 及以上，「每天定时」「只跑一次」要准点触发就得在系统里授予。没授权时会降级成不精确的闹钟（可能晚几分钟），周期兜底照常工作。开启入口在「设置 → 软件权限 → 精确闹钟」。
- **通知使用权**：触发方式选「收到通知」时必须有。入口在「设置 → 软件权限 → 通知使用权」，点进去由系统设置页勾选（部分机型叫「通知读取权限」）；没勾选的话这类任务收不到任何通知。
- **后台运行白名单**：部分国产系统会限制后台唤醒，把 Aharou 加进电池白名单能明显提高可靠性（见「电池优化白名单」）。

## 出问题怎么看

- **没跑**：先看任务是否启用、是否已达运行上限；再看任务列表里的「上次结果」与目标会话里有没有那一轮记录。
- **事件触发了却没跑**：看上一条是不是「条件不满足」「防抖中」或「上一次还在跑」；通知类还要确认「通知使用权」开着。
- **标了「上次错过未补跑」**：说明该跑的时候应用没在运行，属预期行为，下一次会照常。
- **时间不准**：检查「精确闹钟」权限有没有给；再看系统有没有把 Aharou 的后台唤醒限制掉。
- **跑得很慢或没结论**：和普通对话一样，去目标会话里看这一轮的工具调用与输出。
