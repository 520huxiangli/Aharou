# 影子屏

影子屏是一块**不在设备屏幕上显示**的虚拟显示屏。Agent 可以在里面启动 App、截图、点按滑动、按键——你照常用手机，互不打扰。（机制改编自 scrcpy，Apache-2.0）

「设置 → 更多 → 影子屏」是它的开关。

## 前提：root 或 Shizuku 就绪

影子屏由宿主命令通道拉起：有 root 走 root（uid 0），否则走 Shizuku（adb shell）。两条都不可用时页面会提示「需要 root 或 Shizuku 就绪才能使用（当前：…）」，此时点「启动」不会生效。配法见[宿主执行后端](/guide/shizuku)。

## 启动与停止

- **启动**：创建虚拟屏，默认 1080 × 1920、dpi 440；成功后状态行显示「运行中 · display 编号 · 1080×1920」。
- **停止**：销毁虚拟屏，跑在里面的 App 一并结束。

分辨率和 DPI 在设置页**不可改**，页面只有启动与停止两个按钮。需要别的尺寸时，由 Agent 调用 `vscreen start` 时传 `width` / `height` / `dpi`。

## Agent 能做什么

Agent 有一个 `vscreen` 工具：

| 动作 | 说明 |
| --- | --- |
| `start` | 创建虚拟屏，可带 `width` / `height` / `dpi`（默认 1080 / 1920 / 440） |
| `status` | 查看当前状态与 displayId |
| `launch` | 在影子屏里启动 App，`component` 填「包名/Activity」或只填包名 |
| `shot` | 截取影子屏画面；传 `ocr=true` 则不返图片，改用本机 OCR 返回屏幕上的文字。截图会叠加半透明坐标网格，**网格上标的数字就是 `tap` 要用的坐标** |
| `tap` / `swipe` | 在影子屏里点按、滑动（`swipe` 默认 300 毫秒） |
| `type` | 往影子屏的输入框里打字：`text` 填内容，`submit=true` 会在输入后按一次回车。中英文都能打（中文走剪贴板粘贴） |
| `key` | 发送按键，支持 `KEYCODE_xxx` 或 `4` 这类数字 |
| `task` | 给一句话目标，让手机操作子代理在影子屏上自己完成多步操作（见下「手机操作任务」） |
| `trace` | 列出或回放手机操作记录（见下「手机操作任务」） |
| `stop` | 停止影子屏 |

这些操作只作用于影子屏，**不会把 App 拉到你的主屏**。Agent 每次要用 `vscreen` 都会弹一次确认框（「确认使用影子屏」），并把要启动的组件、按键原样显示出来。

## 带 label 的敏感动作

点按（`tap`）与输入（`type`）可以带一个 `label`——**手指下或目标元素上的文字**（按钮、链接、输入框的标签）。它的用途是：动作本身看不出会不会「提交」，于是按屏幕上的文字做二次风控。

- 命中敏感词（「确认支付」「立即支付」「转账」「提交订单」「立即购买」「付款」「发送」「删除」「退出登录」等）时，本次调用会提级为**敏感操作**：弹窗标题变成「敏感操作确认（不可记忆）」，**必须逐次确认**，而且**不会被「始终允许」记住**——点过一次也不会在后续自动放行。
- 不传 `label` 会收到一条告警：手指下是什么无从得知，也就无从判断它会提交什么。

无障碍工具（[无障碍与小染](/guide/accessibility)）里的 `tap` / `setText` 也支持同样的 `label`。

## 截图会带一行语义说明

每次 `shot`（以及无障碍截图）返回的除图片外，还会附一行说明，形如：

```
应用名 (包名) · Activity · 1080×1920 · keyboard shown
```

也就是**哪个 App、哪一屏、多大、键盘是否弹出**——拿不到的字段自动略去。给模型这一行，它就不必只靠像素猜自己在哪。

## 手机操作任务（多步自动执行）

不想一步步盯着点，可以让 AI 用 `task` 下一个**一句话目标**，它会在影子屏上自己走「看屏 → 决策 → 点按 → 再看屏」的多步循环：

- `goal`：要完成的事（一句话）。
- `app`：可选的起始 App（名称或包名），给了就先打开它。
- `maxSteps`：可选的步数上限（默认不设上限）。
- `model`：可选的操作模型（需支持图片输入），不填则复用当前会话的模型。

一次调用只返回**一个结果**，不会把每一步都灌进主对话的上下文。过程中：

- 遇到**密码、验证码、支付确认**这类必须人工完成的界面，会主动把控制权交回给你（见下「接管」）；命中敏感词的设备动作同理。
- **每步都等界面稳定再判断**：点完不会马上截图猜下一步，而是等画面确实变了、并且连续几次采样都一样才重新看。等不到稳定（比如页面一直在转圈）就按当前画面继续，不会卡在那里不动；等待有上限，超时也不算动作失败。
- 有**空转保护**：同一个动作反复做、屏幕却没变化，或者连续几步都是认不出的动作，会先提醒自己换一种做法；连着 6 步都没效果就中止，并告诉你「连续 N 步在影子屏上都没有产生有效动作」。所以它卡住时你看到的是一条带原因的结束说明，而不是一直转圈。
- **每一步都有记录**。用 `trace` 动作可以列出全部任务记录，或传 `traceId` 回放某一次的逐步经过（含每步截图与动作）。

## 接管

当 AI 卡在登录、验证码、支付这类必须由你本人完成的界面时，它会把执行权交回给你：

- 聊天里会出现一张**接管卡片**（标题「AI 正在等你操作」），上面写明「请你完成：……」。
- 你按提示操作完，点卡片上的「**我已完成**」，AI 会重新观察当前界面、接着往下做——不会重做你已经做过的步骤。
- 没有待接管时，卡片位置只留一个「接管」入口，你也可以主动把浏览器 / 影子屏拿过来自己操作，完成后再点「我已完成」交还。

这套接管对**浏览器、影子屏、无障碍**三种操作都适用；浏览器上的「接管」入口见[内置浏览器](/guide/browser)。

## 读屏：没有视觉能力的模型也能用

截图默认以图片形式返回给模型，需要模型支持图片输入。模型不支持时，Agent 有两条路拿到屏幕上的文字：

- **自动**：发送前检测到当前模型不吃图片，就先用本机 OCR 把截图（以及其他图片附件）转成文字再发；开关在「设置 → AI 配置 → 默认模型 → 为无视觉模型识别图片」，默认开启。
- **显式**：调 `vscreen shot` 时传 `ocr=true`，直接返回识别出的文字、不返图片，省一次图片传输。

识别用的是内置的 Tesseract，**全在本机完成、不上传任何图片**，中文简体与英文开箱可用。它适合屏幕界面这类印刷体文字；手写体、复杂排版（如手写笔记照片、公式）识别不了 —— 那种场景去「默认模型 → 识图模型」绑一个多模态模型，走云端分析。

## 聊天页的实时画面

Agent 用过 `vscreen` 的会话里，工具卡片会显示影子屏的实时画面（每 2 秒抓一帧）；影子屏没在跑时显示「影子屏未运行」。

点开工具行进入「Aharou Computer」详情面板，同一画面会**放大展示**（每 1.5 秒刷一帧），下面照旧带这次调用的参数与结果 —— 想看清 Agent 在影子屏里到底点了哪儿，看这里比看卡片上的小图清楚得多。

## 几个边界

- **启动要等几秒**：创建后需等系统把显示就绪，最长约 10 秒；超时会提示「影子屏启动超时」并附上日志尾部。
- **App 已在别处运行**：目标 App 已经在主屏跑着时，`launch` 会把请求交给已有实例，可能直接报错，而不是在影子屏里新起一个。
- **进程没了屏就没了**：影子屏依附于后台进程，进程被系统杀掉后虚拟屏消失，需要重新启动。
- **displayId 每次都可能不同**：以设置页状态行显示的为准。
