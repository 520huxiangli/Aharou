# 影子屏

影子屏是一块**不在设备屏幕上显示**的虚拟显示屏。Agent 可以在里面启动 App、截图、点按滑动、按键——你照常用手机，互不打扰。（机制改编自 scrcpy，Apache-2.0）

「设置 → 运行环境 → 影子屏」是它的开关。

## 前提：root 或 Shizuku 就绪

影子屏由宿主命令通道拉起：有 root 走 root（uid 0），否则走 Shizuku（adb shell）。两条都不可用时页面会提示「需要 root 或 Shizuku 就绪才能使用（当前：…）」，此时点「启动」不会生效。配法见[宿主执行后端](/guide/shizuku)。

## 启动与停止

- **启动**：创建虚拟屏，默认 1080 × 1920、dpi 440；成功后状态行显示「运行中 · display 编号 · 1080×1920」。
- **停止**：销毁虚拟屏，跑在里面的 App 一并结束。

分辨率和 DPI 在设置页**不可改**，页面只有启动与停止两个按钮。需要别的尺寸时，由 Agent 调用 `vscreen start` 时传 `width` / `height` / `dpi`。

## Agent 能做什么

Agent 有一个 `vscreen` 工具：

| 动作 | 说明 |
| --- | --- |
| `start` | 创建虚拟屏，可带 `width` / `height` / `dpi`（默认 1080 / 1920 / 440） |
| `status` | 查看当前状态与 displayId |
| `launch` | 在影子屏里启动 App，`component` 填「包名/Activity」或只填包名 |
| `shot` | 截取影子屏画面；传 `ocr=true` 则不返图片，改用本机 OCR 返回屏幕上的文字 |
| `tap` / `swipe` | 在影子屏里点按、滑动（`swipe` 默认 300 毫秒） |
| `key` | 发送按键，支持 `KEYCODE_xxx` 或 `4` 这类数字 |
| `stop` | 停止影子屏 |

这些操作只作用于影子屏，**不会把 App 拉到你的主屏**。Agent 每次要用 `vscreen` 都会弹一次确认框（「确认使用影子屏」），并把要启动的组件、按键原样显示出来。

## 读屏：没有视觉能力的模型也能用

截图默认以图片形式返回给模型，需要模型支持图片输入。模型不支持时，Agent 有两条路拿到屏幕上的文字：

- **自动**：发送前检测到当前模型不吃图片，就先用本机 OCR 把截图（以及其他图片附件）转成文字再发；开关在「设置 → 默认模型 → 为无视觉模型识别图片」，默认开启。
- **显式**：调 `vscreen shot` 时传 `ocr=true`，直接返回识别出的文字、不返图片，省一次图片传输。

识别用的是内置的 Tesseract，**全在本机完成、不上传任何图片**，中文简体与英文开箱可用。它适合屏幕界面这类印刷体文字；手写体、复杂排版（如手写笔记照片、公式）识别不了 —— 那种场景去「默认模型 → 识图模型」绑一个多模态模型，走云端分析。

## 聊天页的实时画面

Agent 用过 `vscreen` 的会话里，工具卡片会显示影子屏的实时画面（每 2 秒抓一帧）；影子屏没在跑时显示「影子屏未运行」。

点开工具行进入「Aharou Computer」详情面板，同一画面会**放大展示**（每 1.5 秒刷一帧），下面照旧带这次调用的参数与结果 —— 想看清 Agent 在影子屏里到底点了哪儿，看这里比看卡片上的小图清楚得多。

## 几个边界

- **启动要等几秒**：创建后需等系统把显示就绪，最长约 10 秒；超时会提示「影子屏启动超时」并附上日志尾部。
- **App 已在别处运行**：目标 App 已经在主屏跑着时，`launch` 会把请求交给已有实例，可能直接报错，而不是在影子屏里新起一个。
- **进程没了屏就没了**：影子屏依附于后台进程，进程被系统杀掉后虚拟屏消失，需要重新启动。
- **displayId 每次都可能不同**：以设置页状态行显示的为准。
