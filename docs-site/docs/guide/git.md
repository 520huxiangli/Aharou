# Git 版本管理

在项目工作区打开 Git 页面，可以可视化地管理代码版本。底部有三个标签页：状态、分支、提交。如果当前目录不是 Git 仓库，可一键初始化为空白仓库，或输入远程地址直接克隆已有仓库：当前工作区还是空的就直接克隆进去（不新建、不改名），否则会新建一个独立工作区（名字撞车时自动加后缀）并自动切换过去。

右上角的钥匙图标进入「凭据与署名」页，里面有署名和凭据两个标签页——**首次使用必须先配好署名，否则无法提交**。

## CI 与 Pull Request

仓库的远程地址指向 GitHub（`github.com`）时，Git 页顶部会多出一块「**CI / Pull Request**」卡片；其它远程地址不显示这一块。

- 卡片列出**当前分支关联的 Pull Request**：`PR #编号 标题`，下方是它的状态（开放中 / 草稿 / 已合并 / 已关闭）。点这一行用浏览器打开它在 GitHub 上的页面。
- 下面一行是这条 PR 最新提交的 **CI 结论**：CI 通过 / CI 失败 / CI 进行中 / CI 已完成 / 无 CI 检查。失败时还会再列最多三个失败的检查项名称。
- **CI 失败时**，卡片底部会出现「**让 AI 分析并修复**」：点它会把失败摘要（PR 编号、标题、链接与失败项）作为一条消息送进当前会话，让 AI 接着定位问题。
- 右上角的刷新按钮手动重新拉取。
- 当前分支没有关联 PR 时显示「当前分支暂无关联的 Pull Request」。

私有仓库，或频繁刷新触发 GitHub 限流时，卡片会给出「**设置 GitHub 令牌**」入口，粘贴一个个人访问令牌（PAT）即可。令牌只存在本机，**不会写进 Git 的凭据文件**。

常见提示：

| 提示 | 含义 |
| --- | --- |
| GitHub 令牌无效或已过期 | 换一个有效的 PAT |
| 无权访问该仓库（可能需要令牌或更多权限） | 令牌缺权限，或需要授权 |
| 未找到仓库或 Pull Request（私有仓库需要令牌） | 地址或权限不对，私有库要先填令牌 |
| GitHub API 触发限流，约 N 分钟后可重试 | 等提示的时间过去再刷新 |
| 网络不可用，无法连接 GitHub | 检查网络与代理 |

## 状态

看当前仓库的工作区状态。

顶部卡片显示当前分支名、相对远程领先或落后多少个提交（上下箭头），以及已暂存、已修改、未跟踪的文件数量。

**提交**是全宽的主按钮，需要先暂存改动并配好署名才能点，点击后填提交信息（弹窗里的便利功能见本节末尾）。提交下面一行是四个次级按钮：**暂存全部 / 储藏 / 拉取 / 推送**。

- **暂存全部**：把所有改动加入暂存区（没有改动时置灰）。
- **储藏**：打开**储藏箱**，把当前改动先收起来。储藏时可填说明、勾选「包含未跟踪文件（-u）」；每条记录可以**弹出 (Pop)**、**应用 (Apply)**、**丢弃 (Drop)**，也能「清空全部」。丢弃与清空都不可撤销，执行前会二次确认。
- **拉取 / 推送**：需要已配置远程仓库（没有远程时置灰）。当前分支没有上游时，推送会自动建立关联。
- **推送 master 时的提醒**：本地分支叫 `master` 时，推送前会问你是否**重命名为 main 再推**（GitHub 与 GitLab 推荐 main 作默认主分支），可以选「重命名为 main 并推送」或「保留 master 推送」。
- **全部取消暂存**：在已暂存分组标题右侧，执行前会二次确认。这个操作只是取消暂存，不会删除文件内容。
- **全部回退**（**v1.11.0-dev 起**）：在已修改分组标题右侧，把所有未暂存的改动还原成上次暂存或提交的内容。已暂存的内容不受影响，但丢弃掉的改动找不回来，执行前会二次确认。

提交弹窗里除了信息输入框，还有几个便利功能：

- **快捷前缀胶囊**：一行 `feat` / `fix` / `docs` 等类型标签，点一下就插到信息开头。
- **AI 生成**：在标题栏右侧，点它读当前暂存与工作区的差异，让模型写一条提交信息填进去（生成期间显示「正在生成…」；没有差异会提示无法生成）。
- **追加到上次提交 (--amend)**：弹窗底部有个开关，打开后提交会 amend 上一条提交，而不是新建一条。

文件改动按「已暂存 / 已修改 / 未跟踪」分成三组：

- 已暂存：点行看暂存区与上次提交的差异，行尾「−」取消暂存。
- 已修改：点行看工作区与上次提交的差异，行尾「+」暂存该文件。被删除的文件也在这一组，状态徽标是红色的 D。
- 未跟踪：点行看这个新文件的内容（整份按新增显示），行尾「+」暂存。git 会把新建的目录折叠成一行（如 `feature/`），点它展开里面的文件，再点单个文件就能看内容。

如果工作区有未提交的改动，点「拉取」会先提示可能产生冲突，确认后才执行。

### 合并冲突

合并后如果两边改了同一处，状态页顶部会出现**「存在冲突」分组**，与已暂存、已修改、未跟踪并列。处理方式：

- 点冲突文件用编辑器打开，把冲突标记改完保存，再像普通改动一样暂存；
- 改完暂存后照常提交，这个提交就是合并提交；
- 不想继续了就点分组标题旁的**「中止合并」**——会放弃未解决的冲突改动，把工作区还原回合并前的样子（执行前会确认）。

合并操作本身在**分支**页，见下文。

## 回退与删除（v1.11.0-dev 起）

::: tip 版本说明
状态页的长按操作菜单（回退改动、恢复文件、删除未跟踪项）与「全部回退」从 v1.11.0-dev 起提供。
:::

**长按任意文件行**会从底部弹出操作菜单，菜单顶部显示完整路径。可用的操作按文件所在分组不同：

| 分组 | 菜单项 |
| --- | --- |
| 已暂存 | 查看差异、回退改动（还原到上次提交，已暂存和未暂存的改动都会丢）、复制路径 |
| 已修改 | 查看差异、回退改动（还原成上次暂存或提交的内容）、复制路径 |
| 已修改中被删除的文件 | 查看差异、**恢复文件**（从上次提交把文件取回来）、复制路径 |
| 未跟踪文件 | 查看差异、**添加到 .gitignore**（忽略此文件 / 忽略同类型文件 `*.ext`）、删除文件、复制路径 |
| 未跟踪目录 | **添加到 .gitignore**（忽略整个目录）、删除目录、复制路径 |

「添加到 .gitignore」会把对应规则直接追加到工作区的 `.gitignore`（已存在则不重复写），适合刚生成、不想入库的构建产物。

两类操作的后果完全不同，注意区分：

- **回退改动 / 恢复文件**：针对 Git 已经跟踪过的文件。内容存在版本库里，所以无论文件是被你删的、还是被终端命令或 AI 删的，都能取回来。代价是这次没提交的改动会丢失。
- **删除文件 / 删除目录**：只出现在未跟踪项上。这些文件从来没进过版本库，**删除后 Git 无法恢复**。

所有回退和删除操作执行前都会弹确认框，说明会丢什么。

## 分支

分成 HEAD、本地分支、远程分支、标签四组显示。当前分支卡片会显示分支名和三类引用的数量。本地分支按路径树形展示，当前分支高亮。

**切换分支**：点任意分支或标签，确认后切换。点远程分支会创建一个本地跟踪分支再切过去。切换到标签会进入 detached HEAD 状态（此时的提交不属于任何分支，注意别在这个状态下长期工作）。

**合并分支**：点要合进来的那个分支 → 操作菜单 → 「合并分支」，确认后把该分支合并到当前分支（弹窗里会写明把哪个分支合并到哪个）。菜单/弹窗里还有一个「创建合并提交（--no-ff）」开关，开着时即使可以快进也会额外生成一个合并提交。合并后没冲突就直接完成，有冲突回到状态页处理（见上文「合并冲突」）。

**新建分支**：点本地分支分组标题右侧的 +，填分支名、选基准分支（默认当前分支），「创建并切换」开关默认开启。

**重命名分支**：点本地分支，在弹出的操作菜单里选「重命名」。

**删除分支**：点分支 → 操作菜单 → 删除。

- 本地分支用的是安全删除，只能删已合并的分支；未合并的分支会被拒绝并告诉你原因。
- 远程分支的删除会直接作用到远端，**不可撤销**。
- 当前所在的分支不能删。

**标签**：点标签分组标题右侧的 + 从当前 HEAD 创建轻量标签；点已有标签 → 操作菜单 → 删除可以删本地标签。

## 提交

显示首批最近 **100** 条提交，带彩色的分支拓扑图。每条显示短哈希、作者、相对时间、提交信息，以及所在分支或标签的标记。顶部有**搜索框**，可按提交说明或作者过滤。

点一条提交会弹出底部详情面板：完整提交信息、作者与时间、完整哈希（短哈希和完整哈希都可以复制）、是否是合并提交，以及这次改动的文件清单。点文件可以看该文件的差异。

面板里还能直接对这条提交做三个操作：

- **基于此提交创建分支**；
- **在此提交创建标签**；
- **重置到此提交 (Reset)**——可选 Soft（保留工作区与暂存区）或 Mixed（保留工作区，清空暂存区），执行前会确认。

往下滚动接近底部时会自动加载更早的提交（每批 100 条），全部加载完会显示「没有更多了」。

## 超大文件与超大输出

为保护手机内存，Git 页面不会把超大内容整个读进来：

- **文件差异**：单侧文件超过 2MB 时直接提示「文件过大」，不展示内容（二进制文件同理）。
- **命令输出**：状态、分支、提交列表等读取 git 输出超过上限时，会提示「输出过大，已截断，请缩小范围后重试」，不再尝试加载。

## 常见错误提示

操作失败时 Git 的原始报错会被翻译成中文提示：

| 场景 | 提示 |
| --- | --- |
| 删除当前所在分支 | 无法删除当前所在分支，请先切换到其他分支 |
| 删除有未合并提交的分支 | 该分支有未合并的提交，无法安全删除 |
| 切换到不存在的分支 | 分支或引用不存在 |
| 切换时本地改动会被覆盖 | 本地有未提交的改动会被覆盖，请先提交或暂存后再切换 |
| 推送被拒（远程有更新） | 推送被拒绝，远程有更新的提交，请先拉取 |
| 远程鉴权失败 | 远程鉴权失败，请检查凭据配置（用户名/密码/Token） |
| 未配置提交署名 | 尚未配置提交署名，请在设置中填写用户名和邮箱 |
| 未配置远程仓库 | 未配置远程仓库，无法推送/拉取 |
